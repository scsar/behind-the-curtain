# 인형 AI와 아군 봇 설계

작성 2026-09-22, 정리 2026-09-23. 목적: 연출가의 적응이 **배치뿐 아니라 행동으로** 드러나게 한다(U4r 플레이 기록: "배치만 바뀌어서 감이 안 온다"). 사람이 모자랄 때 4~5인 파티를 채울 아군 봇도 같은 구조로 만든다.

**핵심 논지: 다양성.** 인형의 행동은 역할 하나로 정해지지 않는다. 같은 상황이라도 인형마다 다르게, 같은 인형이라도 상태에 따라 다르게 반응해야 한다. 가능성을 좁히는 규칙보다 **넓히는 구조**를 먼저 만든다(아래 "인형 상태").

## 정한 것

| 질문 | 결정 |
|---|---|
| 연출가는 누구를 배우나 | **파티 전체 + 개인별.** 파티 경향으로 진형을 바꾸고, 개인별 경향으로 표적 행동(누구를 막을지, 누구를 쫓을지)을 정한다 |
| 봇의 행동도 배우나 | **사람만 배운다.** 봇의 공격은 관찰에서 뺀다. 연출가가 봇의 고정 패턴에 맞춰 사람에게 엉뚱한 대응을 하지 않게 한다 |
| 파티 역할 | **자유 빌드.** 무기·장비로 역할이 정해진다. 봇은 파티에 부족한 쪽을 스스로 판단한다(공격 속성·파츠 정리 후 상세화) |
| 첫 구현 | **인형 행동 먼저.** 봇은 이 문서에만 둔다 |
| 역할은 규칙인가 | **기본값이다.** 모든 역할이 같은 행동 후보를 갖고, 가중치 0은 금지가 아니다(2026-09-23) |
| 역할은 인형의 정체성인가 | **아니다.** 행동은 장비가 여는 능력에서 나오고, 배역(Guard / Attacker / Healer)은 연출가가 교전마다 주는 지시다. 장력은 가능한 행동의 우선순위만 조정하고 없는 능력을 만들지 않는다. 능력은 태그로 시작하고 개체당 2~3개. 예전 역할 표는 장비 프리셋으로 옮겨 회귀 기준으로 남긴다(2026-10-05, 아래 "능력 기반 행동") |
| 장비 데이터는 누가 쓰나 | **플레이어, 인형, 아군 봇, 시뮬레이션 플레이어가 같은 정의를 쓴다.** 행동 규칙(판단 계층)은 편마다 다르다(2026-10-05) |
| 배역은 무엇인가 | **행동 계약이다.** 목표, 우선 행동, 대체 행동으로 이루어지고, 능력으로 걸러도 기본 행동으로 끝나므로 수행할 능력이 없어도 멈추지 않는다. 처음에는 한 개체에 배역 하나. 배역은 능력을 덮어쓰지 않고 능력의 사용 순서와 목적을 바꾼다(2026-10-05) |
| 장비는 공짜인가 | **아니다. 능력과 함께 비용이 있다.** 처음에는 이동·회전 속도 배율과 사용 중 이동 불가 두 가지. 자유도는 "다 할 수 있음"이 아니라 "서로 다른 대가를 고름"이다(2026-10-05) |
| 그럼 연출가는 무엇을 하나 | **행동을 고르지 않고 판을 짠다.** 배우고(관찰·기억), 장비를 나눠 주고(후보), 배역을 나누고, 무대를 짜고, 실을 쥔다. 교전을 넘어 배우는 것은 연출가뿐이다. 연출가가 의미를 잃지 않았는지는 연출가를 끈 판과 비교해 잰다(2026-10-05, 아래 "연출가: 판을 짜는 존재") |
| 학습 방식 | **세기와 규칙으로 배운다. 학습된 모델은 쓰지 않는다.** 설명 가능, 결정론, 조절 가능을 위해서다(2026-10-05) |
| 검증을 누가 하나 | **시뮬레이션 플레이어(테스트용 봇)가 연출가와 서로 배우며 먼저 거르고, 사람의 Play는 재미와 가독성을 본다.** 시뮬레이션 플레이어는 보이는 단서만 입력으로 받고, 연출가에게는 사람으로 보인다(2026-10-05, 아래 "시뮬레이션 플레이어와 쌍방 학습") |
| 인형의 성향은 어디서 오나 | **결(연속적인 축).** 출신으로 정하지 않는다. 인형도 무기를 자유롭게 장착하므로 출신은 겉모습과 이야기에만 쓴다(2026-09-23) |
| 결의 첫 축 | **대담 ↔ 신중, 혼자 ↔ 무리.** 거리·위치와 아군에 대한 반응으로 바로 보인다. 집착 ↔ 변덕(대상을 얼마나 오래 붙잡나)은 장력 저하의 전조와 섞여 읽기 어려우므로 다음 단계로 미룬다(2026-09-23) |
| 적의 종류 | **인형과 인형화된 사람.** 실이 끊기면 인형은 풀려나고, 사람은 잠깐 그로기 뒤 다시 연결된다(2026-09-23) |
| 연출가의 조율 | **예산이 한정되어 있다.** 연출가도 완벽하지 않다(2026-09-23) |
| 쓰러진 개체의 실은 | **쓰러뜨린 방법에 따라 연출가에게 돌아간다.** 부순 인형의 실은 돌아가고, 풀어 준 인형의 실은 끊겼으니 사라진다. 구출한 사람의 실은 사람의 의지와 엉켜 있어 **일부만** 돌아간다. 돌아온 실은 조율 예산을 늘린다(상한 있음). 부수기와 풀어 주기가 다른 결과가 된다(2026-09-23) |
| 연출가는 모두 같은가 | **아니다.** 연출가마다 결이 있어 조율 방식과 대응 선호가 다르다(2026-09-23) |
| 인형화된 사람을 방패로 세우나 | **전용 대응을 두지 않는다.** 인형화된 사람은 진행하려면 어차피 쓰러뜨려야 하므로, "사람을 피하는 버릇"은 오래 가는 전략이 아니다. 관찰은 다른 대상과 같은 규칙을 쓴다(2026-09-23) |
| 연출가는 대응을 하나만 고르나 | **아니다. 대응을 두 층으로 나눈다.** 무대 구성(진형, 합동 공격 계획, 약점, 준비 비용)은 하나를 고르고, 행동 의도는 기준값을 넘은 모든 경향을 넘은 정도에 비례해 섞는다. 개인 위협(힐러 위협자 등)은 무대 구성과 상관없이 행동에 반영한다. T5의 "대응 하나" 전제 때문에 힐러 집중과 원거리 지속이 경쟁하면 교전마다 호위와 돌격이 번갈아 나왔다(2026-09-23) |
| 원정이 끝나면 기억은 | **개인 기억은 일부 남기고, 파티 기억은 지운다.** 연출가는 "저 사람, 전에도 힐러를 노렸지"를 기억한다. 파티 구성은 원정마다 다를 수 있으므로 파티 기억은 남기지 않는다(2026-09-23) |
| 연결 실 파츠 = 카운터의 Thread 연결부? | **별개다**(`docs/planning.md`). 신호 장치와 Signal도 별개다 |
| 관통은 카운터에도 적용되나 | **적용하지 않는다.** 일반 공격과 파츠 기회 공격에만 적용한다. Shoot의 몸통 가림과 "돌아 들어가서 쏘기"를 유지한다(`docs/planning.md`) |

## 구조

```
[연출가]  교전 사이에 대응을 정한다 (두 층)
   │        무대 구성: 하나 (진형, 합동 공격 계획, 약점)
   │        행동 의도: 기준값을 넘은 경향을 섞은 가중치 + 개인 위협
   │        배역: 능력을 보고 나누는 행동 계약 (T16b-2)
   │        장비 배분: 관문 사이 (후보)
   │      교전 중에는 실 장력을 조율한다(예산 한정)
   ▼
[블랙보드]  편마다 하나 (인형 편 / 플레이어 편)
   사실: 위치, 방향, 누가 누구를 치는지, 합동 공격 단계, 노출된 연결부
   의도: 인형 편은 연출가가, 플레이어 편은 파티 구성이 올린 우선순위
   예약: "이 대상은 내가 막는다", "이 연결부는 내가 끊는다" (중복 방지)
   ▼
[개체별 행동 선택 (Utility AI)]  몇 tick마다 후보 행동에 점수를 매겨 하나를 고른다
   능력이 후보를 정하고, 배역·의도·결·상황이 순서를 정하고, 실 장력이 배역의 강제력을 정한다
```

**원칙**

1. **판단은 전부 `src/Core`에 둔다.** tick 기반 시간, 시드 고정 난수를 쓴다. 같은 입력이면 같은 결과가 나오므로 테스트할 수 있고, 나중에 서버가 판정하는 구조로 옮길 수 있다. Unity는 Core가 정한 이동과 행동을 보여 주기만 한다.
2. **연출가는 행동을 직접 고르지 않는다.** 행동 점수의 가중치와 실 장력만 바꾼다. 같은 인형이라도 대응에 따라 다르게 움직이고, 교전 중의 상황에는 행동 선택이 반응한다.
3. **의도는 교전 사이에만 바뀐다.** 기획의 "전술 수정은 교전 사이에 적용"을 지킨다. 교전 중에 바뀌는 건 개체의 몸·장력·상황과, 연출가가 실을 붙잡는 조율뿐이다. 조율은 대응을 바꾸는 게 아니다. 그래서 플레이어는 "이번 교전의 인형들은 이런 의도로 움직인다"를 읽을 수 있다.
4. **왜 그렇게 움직이는지 보여야 한다.** 각 개체의 현재 행동과 대상을 화면에 표시할 수 있게 Core가 노출한다(AGENTS.md Unity 규칙). 이 표시는 개발·리뷰용이고, 플레이어에게는 행동 자체가 단서다. 연출가가 대응을 바꿨다는 사실을 알리는 UI는 기본 화면에 두지 않고 보조 옵션 후보로만 둔다(`docs/planning.md` "적응 변화의 전달 원칙"). 플레이어는 인형의 간격, 보호 위치, 이동 방향, 파츠 노출 방향, 준비 동작으로 이전 교전과의 관계를 추론한다.
5. **대응은 교환이다.** 기존 전략을 무효화하지 않고 다른 선택을 요구한다. 특정 파츠를 보호하면 다른 파츠나 진형에 약점이 생기고, 신호를 분산하면 각 신호의 보호가 약해진다. 행동 선택에는 새 약점이 포함되어야 한다.
6. **임시 압박(U3d 파티 회전과 바닥 경고)은 이 구조로 대체했다**(U5). 그 위에 새 기능을 쌓지 않는다.

## 월드 상태 (`src/Core`)

- 평면 좌표(x, z), 방향, 반지름. 장애물과 높이는 아직 없다.
- 개체: id, 편(인형/플레이어), 사람인지 봇인지, 인형 역할(Guard/Attacker/Healer), 위치, 현재 행동과 대상.
- 플레이어의 이동은 입력을 Unity가 Core에 넘기고, 인형과 봇의 이동은 Core가 정한다. Unity는 매 프레임 Core의 위치를 보간해 그린다.
- 체력과 피해는 T16에서 넣는다. 그전까지는 "공격이 닿았다" 사건만 기록한다.

## 관찰: 파티 + 개인별

- `AttackEvent`에 공격자 id와 사람/봇 구분이 있다. 봇의 공격은 기록하지 않는다.
- 파티 경향(지금의 세 경향)은 진형과 대응을 고른다.
- 개인별 경향은 같은 경향을 플레이어마다 따로 센다. 예: "힐러 집중이 가장 높은 플레이어" = 힐러 위협자. 행동 선택이 이 값을 대상 선정에 쓴다.
- **경향은 키로 늘릴 수 있다.** 식별자 → 값의 모음이다. 공격 특성 다섯 가지와 파츠 선호가 이 모음에 더해진다.
- **관찰 대상은 장비가 아니라 반복된 행동이다.** 원소나 무기 이름보다 **플레이어가 어떤 전투 상태를 반복해서 만들었는지**(어떤 특성의 공격 비율, 어떤 파츠를 먼저 노리는지, 노출 기회를 얼마나 살리는지)를 기록한다. 그래서 장비를 추가해도 AI 판단 구조는 바뀌지 않는다.
- **의심도: 빨리 배우고 천천히 잊는다 (2026-09-22 결정, T15 구현).** 연출가는 한 번 본 버릇을 쉽게 지우지 않고 "정말 그만뒀나?" 하며 천천히 경계를 푼다. 기억을 합칠 때 세 경우를 나눈다(수치는 설정, 임의 값). 파티 전체 기억도 같은 규칙을 쓴다.

  | 상황 | 반영 방식 (초안) |
  |---|---|
  | 이번 값이 기억보다 높음 (버릇을 보임) | 빠르게 오름: 이번 값을 50% 반영 |
  | 공격은 했지만 이번 값이 기억보다 낮음 (그 버릇은 안 보임) | 천천히 내림: 20%만 반영 (약 3교전에 절반) |
  | 그 플레이어의 공격 기록이 아예 없음 | 아주 천천히 내림: 10%만 0 쪽으로. "모르는 것"은 "안 한 것"과 다르다 |

  효과: 버릇을 바꾼 플레이어를 Guard가 한두 교전은 계속 따라다니다가 서서히 풀어 준다. 플레이어는 "아직 나를 의심한다"를 행동으로 읽는다.
- **교전 사이에 남는 것과 새로 만드는 것.** 교전마다 월드(위치), 블랙보드(예약·의도), 판단기, 개체 차이 시드를 새로 만든다. 파티 기억과 개인 기억은 원정 동안 남는다.
- **원정 사이 (2026-09-23 결정).** 원정이 끝나면 파티 기억은 지우고, 개인 기억은 CarryOverRatio(초안 0.5)를 곱해 남긴다. 사람은 원정을 넘어 같은 id로 식별되어야 한다(지금 AgentId는 교전 안의 id이므로, 원정을 넘는 플레이어 식별자가 필요하다).

## 대응: 무대 구성과 행동 의도 (2026-09-23 개정)

**T15r Play 기록:** 인형을 끌고 다니며 멀리 있는 힐러를 원거리로 계속 치면, 다음 교전에서는 Guard 하나가 막아선다. 그런데 그다음 교전에서는 다시 셋이 달려든다. 기억이 초기화된 게 아니다. 힐러 집중과 원거리 지속이 **둘 다** 올랐는데, 연출가(`RuleTacticSelector`)가 기준값을 가장 크게 넘은 경향 **하나**에만 대응했기 때문이다. 두 경향이 엎치락뒤치락하면 대응도 GuardHealer와 ShieldAdvance를 번갈아 오간다. 게다가 대응을 고를 때는 파티 기억만 쓰고, 개인 기억은 "누가 위협자인가"를 정하는 데만 쓰였다.

그래서 대응을 두 층으로 나눈다.

| 층 | 무엇 | 몇 개 | 무엇으로 정하나 |
|---|---|---|---|
| **무대 구성** | 진형 배치, 합동 공격 계획, 약점(`TacticWeakness`), 준비 비용 | **하나** | 파티 기억에서 기준값을 가장 크게 넘은 경향(지금의 규칙). 물리적 배치는 하나일 수밖에 없고, T7 공정성 불변식과 약점이 여기에 붙어 있다 |
| **행동 의도** | 행동별 의도 배율(누구를 막고, 쫓고, 얼마나 흩어지나) | **섞는다** | 파티 기억에서 기준값을 넘은 **모든** 경향이 넘은 정도에 비례해 기여한다 |
| **개인 위협** | 힐러 위협자, 원거리 위협자 | 사람마다 | 개인 기억. 무대 구성과 상관없이 행동에 반영한다 |

**무대 구성 표 (지금의 대응)**

| 무대 구성 | 무엇에 대한 대응 | 행동 의도 기여 (가중치를 올리는 행동) |
|---|---|---|
| StandardFormation | - | 기준값 |
| SpreadFormation | 광역 의존 | 서로 거리 벌리기, 광역 공격 준비 동작을 보면 흩어지기 |
| GuardHealer | 힐러 집중 | Guard가 **힐러 위협자를 따라다니며** 힐러와 그 사이에 선다 |
| ShieldAdvance | 원거리 | **원거리 경향이 가장 높은 플레이어에게** 거리를 좁힌다 |

같은 표의 "행동 의도 기여"가 섞기의 재료다. 무대 구성으로 뽑히지 않은 경향도 기준값을 넘었다면 자기 몫만큼 의도를 보탠다.

**섞는 규칙 (초안, 수치는 설정)**

- 경향 t의 세기 s_t: 값 < 기준값이면 0, 아니면 BlendFloor + (1 − BlendFloor) × (값 − 기준값) / (1 − 기준값). BlendFloor(초안 0.5)는 기준값을 막 넘은 경향도 눈에 보일 만큼은 반영하기 위한 바닥이다. 행동 a의 의도 배율 = 1 + Σ_t s_t × (표의 배율_t(a) − 1), 0 미만이면 0. 넘은 정도가 클수록 그 경향의 표에 가까워진다.
- 무대 구성으로 뽑힌 경향도 같은 식을 쓴다. 무대 구성은 배치만 정하고, 행동 의도는 식이 정한다. 그래서 기준값을 막 넘어 뽑힌 대응은 예전(표 그대로)보다 약하게 시작한다.
- 의도 배율은 (역할, 행동) 단위다. 블랙보드 키는 `<역할>:<행동>`이고, 없으면 `<행동>` 키로 떨어진다(T15r). 새 대응을 추가하는 일은 이 표에 행을 더하는 일이다.
- **개인 위협:** 힐러 위협 사실이 있으면 대응과 상관없이 Guard의 막아서기 적합도가 그 사람의 힐러 집중 기억 값 × IndividualThreatInterceptScale(초안 0.5)이다(예전의 고정 0.02배 대신, 0.02는 바닥으로 남는다). GuardHealer는 1이다. 교전 중 보호 반응(아래 "상황")은 이 위에 올라간다. 원거리 위협자의 독립 반영은 T16b(상황)에서 한다.
- **연출가의 결:** 연출가마다 경향별 가중(어떤 경향을 더 무겁게 보나)과 무대 구성 선호가 다르다(아래 "연출가마다 다르다").

**피로도 원칙과의 관계.** "한 관문에서 눈에 띄는 변화는 한두 개"(`docs/worldbuilding.md`)는 변화의 **양**에 대한 원칙이지 대응의 **개수**에 대한 원칙이 아니다. 그래서 섞되 제한한다.

- 교전 사이에 행동별 의도 배율이 바뀌는 폭에 상한을 둔다(MaxIntentShiftPerEncounter).
- 무대 구성은 교전 사이에 한 번에 하나만 바뀐다(지금도 하나다).
- 의심도의 느린 하강이 급한 변화를 이미 막고 있다.

파츠 관련 대응 후보는 아래 "공격 특성과 파츠 연동"에 둔다.

## 능력 기반 행동 (2026-10-05)

**Guard / Attacker / Healer는 인형의 정체성이 아니다.** 행동은 장비가 여는 능력에서 나오고, 배역은 연출가가 교전마다 주는 지시다. 기획서의 "직업이 아니라 무기·장비가 역할을 정한다"(`docs/planning.md` "장비 구조")와 "인형도 무기를 자유롭게 장착한다"를 AI에도 그대로 적용한다. 역할 표는 프로토타입을 빨리 만들기 위한 임시 장치였고, T15r~T17 Play의 원패턴("하나가 나서고, 뒤는 막아서고, 힐러를 치면 하나가 막는다")의 원인 중 하나였다.

```
능력 = 무엇을 할 수 있는가          (장비가 정한다)
결   = 무엇을 선호하는가            (개체가 정한다)
배역 = 이번 교전에서 무엇을 맡았는가 (연출가가 정한다)
상황 = 지금 무엇이 필요한가         (교전이 정한다)
```

같은 방패 인형도 평소에는 자기 생존을 우선할 수 있고, 연출가가 배역을 주면 힐러를 지키고, 실이 느슨해지면 다시 자기 능력과 결대로 움직인다.

### 행동을 고르는 순서

```
행동 후보
→ 능력이 있는가?                없으면 후보가 아니다 (어떤 값도 이걸 바꾸지 못한다)
→ 배역이 우선시키는가?           연출가의 지시
→ 지금 상황에서 점수가 높은가?   상황, 결
→ 장력이 배역을 얼마나 강제하는가?
```

- **장력은 이미 가능한 행동의 우선순위만 조정한다.** 장력이 높다고 없는 회복 장비를 쓰게 되지 않는다. 장력이 낮을 때의 끌림(지금은 비틀거림, T16b-3부터 결)도 능력 안에서만 고른다.
- **능력이 필요 없는 기본 행동:** 다가가기, 거리 유지, 흩어지기, 자리 지키기, 비틀거림, 무기로 공격. 공격 거리와 방식은 무기가 정한다.
- **능력이 필요한 행동:** 막아서기(`Protect`), 막기·버티기(`Block`), 회복(`Heal`), 교란(`Disrupt`) 등.

### 능력은 태그로 시작한다

장비 조합을 일찍 늘리면 테스트 조합이 폭발한다. 그래서 처음에는 능력을 **태그와 행동 묶음**으로 제한한다.

| 구성 | 초기 후보 | 여는 것 |
|---|---|---|
| 무기 프로필 | 사거리 대역(근접 / 중거리 / 원거리)과 공격 특성 하나 | 공격 거리, 공격 방식, 선호 거리의 기본값 |
| 능력 태그 | `Block`, `Protect`, `Heal`, `Disrupt` (후보, 첫 구현에서 확정) | 해당 행동 묶음 |

- **개체 하나는 태그 2~3개만 갖는다.** 행동 폭은 자유롭지만 검증할 수 있는 수준으로 둔다.
- 태그는 장비 데이터에서 나온다(방패 → `Block`, 회복 도구 → `Heal` 등). 개체에 태그를 직접 붙이지 않는다.

### 장비 데이터는 공유하고, 판단 계층은 편마다 다르다

| | 장비 데이터 | 행동을 정하는 것 |
|---|---|---|
| 플레이어 | 공유 | 입력과 빌드 선택 |
| 인형 | 공유 | 연출가의 배역, 실 장력, 결, 상황 |
| 아군 봇 | 공유 | 파티에 부족한 기능, 자기 결, 상황 |
| 시뮬레이션 플레이어(테스트용) | 공유 | 성향 값과 학습(아래 "시뮬레이션 플레이어와 쌍방 학습") |

같은 장비를 쓰는데 왜 다르게 움직이는지는 판단 계층의 차이로 설명된다. 회수한 인형의 개조(생활 콘텐츠)도 같은 데이터 위에서 이어진다.

### 배역은 행동 계약이다

배역은 역할 이름이 아니라 **목표, 우선 행동, 대체 행동**으로 된 계약이다. 연출가가 교전 사이에 인형들의 능력을 보고 나눈다(예: "이번엔 `Protect`가 있는 둘이 회복 담당을 지켜라"). 배역 이름(지금의 Guard / Attacker / Healer)은 남지만 **인형의 속성이 아니라 이번 교전의 지시**다.

```
배역: 회복 담당
목표: 아군의 생존 유지
우선 행동: Heal
대체 행동: Protect → Disrupt → 거리 유지(후퇴)
```

- **배역은 능력을 덮어쓰지 않고, 능력의 사용 순서와 목적을 바꾼다.** 계약의 행동 목록은 그 개체의 능력으로 먼저 걸러진다.
- **대체 행동은 반드시 기본 행동으로 끝난다.** 그래서 걸러도 하나는 남고, 배역을 수행할 능력이 없는 인형도 멈추지 않고 자기 능력으로 기여한다. 예: `Protect`가 없는 인형이 보호 배역을 받으면 → 위협자에게 다가감 → 공격으로 시선을 끔 → 회복 담당이 물러날 공간을 만듦.
- **처음에는 한 개체에 배역 하나.** 보호와 공격을 동시에 요구하는 배역 충돌은 만들지 않는다. "잠깐 공격 후 회복" 같은 판단은 계약 + 결 + 상황 점수에서 저절로 나오는지 먼저 본다(열린 질문).
- 블랙보드의 `<역할>:<행동>` 의도 키는 `<배역>:<행동>`으로 읽는다. 의도 배율은 계약을 숫자로 표현한 것이고, 대응 → 의도 표는 그대로 쓸 수 있다.
- 관찰의 "힐러 집중"은 "회복 배역을 맡은 개체를 노린 비율"이 된다.
- 배역을 줄 개체가 하나도 없으면(예: 계약의 어떤 행동도 걸맞지 않음) 그 배역은 비운다. 연출가의 결이 배역 배분의 우선순위를 정한다.
- **목표는 잰다.** "회복 배역의 목표가 교전 동안 얼마나 지켜졌나"를 시뮬레이션 리포트에서 잰다. 배역이 실제로 의미 있게 작동하는지 숫자로 본다.

### 장비에는 비용이 있다

능력만 있고 대가가 없으면 "다 되는 장비"가 정답이 된다. 원칙 5("대응은 교환이다")를 장비에도 적용한다. 자유도는 **모든 걸 할 수 있음이 아니라, 서로 다른 대가를 고르는 것**이다.

| 장비 예 | 여는 것 | 대가 |
|---|---|---|
| 무거운 방패 | `Block`, `Protect` | 이동·회전이 느림 |
| 회복 도구 | `Heal` | 사용 중 이동 불가 |
| 교란 장치 | `Disrupt` | 채널링 중 이동 불가(방어 취약) |
| 긴 창 | 중거리 공격 | 가까이 붙은 적에게 약함(파츠와 노출, T16c에서) |

처음에는 비용을 두 가지만 둔다: **이동·회전 속도 배율**과 **사용 중 이동 불가**. 나머지는 파츠와 노출(T16c), 공격 특성(T16d)에서 다룬다.

### 읽힘은 장비가 보장한다

**행동은 보이는 장비에서 예측할 수 있어야 한다.** 창을 든 인형은 창 쓰는 사람처럼 움직인다. 플레이어는 무기를 보고 행동을 예상하고, 예상에서 벗어나면 그 원인은 결·실·상황 중 하나이며 보이는 단서가 있다(아래 "다양성의 조건").

### 기존 테스트는 장비 프리셋으로 보존한다

역할 표는 바로 지우지 않고 **장비 프리셋**으로 옮겨 회귀 기준으로 남긴다.

| 프리셋 | 장비 | 예전 역할 |
|---|---|---|
| 방패형 | 근접 무기 + `Block` + `Protect` | Guard |
| 근접형 | 근접 무기 | Attacker |
| 회복형 | 짧은 무기 + `Heal` | Healer |

프리셋 셋에 예전 역할과 같은 배역을 주면 T15r~T17의 금지 패턴·계약 테스트가 그대로 통과해야 한다. 아래 "역할별 계약" 표는 이 프리셋들의 기대 동작으로 읽는다.

## 연출가: 판을 짜는 존재 (2026-10-05)

행동이 능력·결·상황에서 나오게 되면서 연출가의 역할은 **행동을 고르는 존재에서 판을 짜는 존재로** 옮겨 간다. 플레이어가 읽어야 하는 "각본"은 개별 인형의 움직임이 아니라 연출가가 짠 판이다. 인형들이 다양할수록 그 위에 깔린 연출가의 의도가 더 두드러진다. 다 같은 인형이 다 같이 움직이면 각본이 보이지 않는다.

```
인형   = 할 수 있는 것과 하고 싶은 것 (능력, 결)
연출가 = 배운 것으로 판을 짜는 것 (관찰 → 장비 → 배역 → 무대 → 실)
```

| 연출가의 손잡이 | 연출가가 없으면 | 상태 |
|---|---|---|
| **배운다** (관찰, 의심도, 원정 사이 기억) | 인형은 교전 하나만 겪고 끝난다. 교전을 넘어 배우는 것은 연출가뿐이다 | 있음 |
| **장비를 나눠 준다** (관문 사이) | 편성이 고정된다 | **후보(새로 제안)** |
| **배역을 나눈다** (행동 계약) | 개인은 있어도 팀 전략이 없다 | T16b-2 |
| **무대를 짠다** (진형, 합동 공격 계획) | 합동 공격이 없고, 핵심 전투 규칙인 카운터가 사라진다 | 있음 |
| **실을 쥔다** (조율 예산) | 배역을 강제할 힘이 없다 | 있음 |

**장비 배분(후보).** 세계관 문서에 이미 근거가 있다: "관문마다 적 편성·배치·합동 공격과 행동 패턴을 바꾼다", "정찰 구간에서 보이는 진형과 장비로 다음 대응을 알린다". 장비가 행동을 정하는 구조에서는 **연출가가 장비를 바꿔 주는 것이 가장 강력하고 가장 잘 보이는 적응**이다. 예: 힐러를 계속 노리면 다음 관문에서 방패를 든 인형이 늘어난다. 정찰에서 보이므로 읽힘도 좋다. 교환 원칙대로 방패가 늘면 다른 무언가가 줄어야 하고, 피로도 원칙대로 한 관문에서 눈에 띄는 장비 변화는 한두 개로 제한한다.

**연출가가 의미를 잃지 않았는지 잰다.** 인형이 능력·결·대체 행동만으로 너무 잘 움직이면 배역이 행동을 거의 바꾸지 못하고 연출가는 이름뿐이 된다. 그래서 시뮬레이션 리포트에서 같은 시드로 **연출가의 배역·적응·조율을 끈 판과 켠 판**을 비교한다.

- 행동 분포와 결과(카운터, 보호 성공, 뒤에는 피해)가 충분히 달라야 한다. 비슷하면 연출가가 의미를 잃은 것이다.
- 거꾸로 너무 달라서 인형의 결과 능력이 보이지 않으면 연출가가 너무 강한 것이다. 실 장력이 이 균형을 조절하는 손잡이다.

### 시야는 나뉜다: 전황은 연출가, 국지는 인형 (2026-10-05)

**전체 전황을 보고 어떻게 움직일지 정하는 것은 연출가의 고유 영역이다.** 인형은 전황을 보지 않는다. 인형이 보는 것은 자기 주변(가까운 사람과 아군, 자기 몸과 실, 최근에 겪은 일)뿐이다.

| | 연출가 | 인형 |
|---|---|---|
| 보는 것 | 전황 전체: 파티 구성, 누가 무엇을 반복하는가, 어느 인형이 무너지고 있는가, 남은 실과 예산 | 자기 주변: 위협 반경, 가까운 아군, 자기 장비·몸·실, 최근에 겪은 일 |
| 정하는 것 | 판: 장비(후보), 배역(계약), 무대(진형·합동 공격), 실(조율) | 지금 할 행동 하나 |
| 바뀌는 때 | 판은 교전 사이(원칙 3). 교전 중에는 조율과 합동 공격으로만 | 몇 tick마다 |

- **이 비대칭이 "각본과 개인"의 결을 만든다.** 인형이 전황까지 보고 스스로 최적을 고르면 연출가가 필요 없어지고(위 "연출가 끄기 비교"), 연출가가 인형의 행동을 직접 고르면 인형의 결과 능력이 사라진다.
- **교전 중 연출가의 전황 판단은 두 통로로만 드러난다.** 누구의 실을 조이는가(조율 예산), 합동 공격을 언제·누구로 거는가. 둘 다 보이는 동작이 있다(실을 붙잡음, 합동 공격 전조). 교전 중에 배역이나 의도를 바꾸지 않는 것은 원칙 3("의도는 교전 사이에만")과 읽힘을 위해서다.
- **교전 중 지시(예: "모여라", "힐러를 감싸라")를 더할지는 열린 질문이다.** 더한다면 반드시 보이는 신호(인형사의 명령, 실의 움직임)가 있어야 하고, 피로도 원칙대로 한 교전에 한두 번으로 제한한다.
- 인형이 "전황처럼 보이는" 반응(예: 아군이 쓰러지자 모임)을 하는 것은 괜찮다. 그것은 전황 판단이 아니라 자기 주변의 상황(주변 개체, 최근에 겪은 일)에 대한 반응이다.

## 인형 행동

### 행동 후보

모든 개체가 같은 기본 후보를 갖고, 능력이 필요한 후보는 그 능력이 있을 때만 생긴다(위 "능력 기반 행동"). id는 `ActionIds`(`src/Core/IntentionSettings.cs`).

| 행동 | id | 하는 일 |
|---|---|---|
| 다가가기 | `approach` | 대상에게 거리를 좁힌다. 대상은 방패 전진이면 원거리 위협자, 아니면 가장 가까운 사람 |
| 공격 | `attack` | 공격 거리 안의 대상을 친다 |
| 자리 지키기 | `hold` | 진형 자리(배역에 따라 앞자리 / 뒷자리)를 지킨다 |
| 막아서기 | `intercept` | 보호할 아군과 위협자 사이에 선다. 블랙보드 예약으로 한 명만 맡는다. `Protect` 능력이 필요하다(T16b-1부터) |
| 흩어지기 | `spread` | 다른 인형과 간격을 벌린다 |
| 거리 유지 | `keepDistance` | 가장 가까운 사람과의 거리를 KeepMin(5m) ~ KeepMax(8m)로 유지한다 |
| 미끼 (후보) | - | 파츠를 일부러 노출해 플레이어를 유인하고, 반대편에서 다른 인형이 행동한다. 아래 열린 질문 |

- 점수 = 요소별 곡선의 곱 × 의도 가중치 × 개체 상태(아래 "인형 상태"). 재평가 주기는 몇 tick(예: 6tick = 0.2초)이고, 인형마다 시점을 엇갈린다.
- **지속 보너스:** 지금 하던 행동에 가산점을 줘서, 점수가 비슷할 때 행동이 흔들리지 않게 한다.
- 동점은 시드 난수로 가른다.
- 합동 공격 전조와 카운터 창 동안의 행동은 열린 질문이다.

### 새 행동 추가 절차 (2026-10-05)

행동 다양성은 행동 후보를 늘려서 만든다. 학습된 모델을 쓰지 않으므로 행동 하나를 추가해도 정책 전체를 다시 학습할 일이 없다. 다른 행동의 코드는 건드리지 않고, 후보 하나와 표의 몇 줄, 테스트 하나가 늘어난다. 남는 비용은 **점수 균형**(새 행동이 다른 행동의 점수를 빼앗는 것)이다. 이것은 세 겹으로 본다. 금지 패턴 테스트는 **정의해 둔 이상한 움직임**(도망, 진동, 군체, 정지 등)을 자동으로 잡는다. 시뮬레이터 지표(행동별 점유율, 다양성)는 **특정 행동이 지나치게 지배하는지**를 숫자로 보여 준다. 그리고 **전투가 재미있는지, 어느 행동을 얼마나 줄일지는 사람이 Play로 판단하고 조정한다.** 테스트가 통과했다고 균형이 맞았다는 뜻은 아니다.

행동을 추가할 때는 아래를 모두 채운다(명령 파일에도 이 틀로 쓴다).

1. **의도와 보이는 단서:** 의도 한 줄, 그리고 행동만 보고 무엇이 읽히는가(위치, 각도, 리듬 중 무엇으로). 단서가 없으면 추가하지 않는다.
1-1. **플레이어의 선택과 적이 내주는 기회:** 이 행동이 나오면 플레이어가 무엇을 새로 판단해야 하는가, 그리고 이 행동을 하는 동안 인형이 어떤 빈틈을 보이는가. 이동 궤적만 다르고 플레이어가 계속 같은 공격을 하게 된다면 화면만 바빠질 뿐이다. 이 두 칸이 비면 행동 설계가 끝나지 않은 것이다(원칙 5 "대응은 교환이다").
2. **적합도:** 언제 할 만한가(조건과 기준값, 설정으로 둠).
3. **목표 지점과 대상:** 어디로 가고 누구를 노리는가.
4. **능력과 계약:** 필요한 능력 태그(없으면 기본 행동), 들어갈 배역 계약과 그 안의 위치(우선 / 대체), 영향을 주는 결의 축(수행 방식, 끌림).
5. **금지 패턴과의 관계:** 기존 금지 패턴과 부딪히는가(예: 물러나는 행동이면 "이유 없는 도망"의 정당한 예외로 넣을지, 예약이 필요한 일인지). 예외를 넣으면 금지 패턴 표에 적는다.
6. **검증:** 그 행동이 나와야 하는 시나리오 테스트 하나, 나오면 안 되는 상황 하나, 시뮬레이터 출력에서 확인할 한 줄. 여럿을 상대로 의미가 갈리는 행동(포위, 보호, 대상 고르기)은 **플레이어 둘 이상**인 시나리오에서 검증한다. 한 사람만 상대하면 모든 인형이 그 한 사람에게 모이는 게 자연스러워 다양성을 평가할 수 없다.

**T16b-3a-1의 세 행동 (설계 완료 기준, 2026-10-05):**

| 행동 | 보이는 단서 | 플레이어의 선택 | 적이 내주는 기회 |
|---|---|---|---|
| 측면 돌기 | 정면에서 벗어나 옆으로 크게 도는 궤적 | 정면 공격을 계속할지, 방향을 돌릴지 | 돌아가는 동안 공격이 늦어진다 |
| 포위 | 인형들이 서로 반대편 각도를 잡음 | 빈 방향으로 빠질지, 한쪽을 집중 공격할지 | 인형 사이가 벌어져 서로 보호하기 어렵다 |
| 견제 | 공격 거리 바로 밖에서 길을 막고 압박만 함 | 거리를 좁힐지, 공격을 유도하고 진입할지 | 견제 공격 뒤 회복 동작에 접근할 수 있다 |

### 행동과 노출

행동마다 **어떤 파츠를, 어느 방향으로, 몇 tick 노출하는지**를 함께 정의한다(예: 공격 = 휘두르는 동안 관절 전방 노출, 회복 = 신호 장치 후방 노출). 파츠는 항상 노리는 약점이 아니라 이런 동작에서 잠깐 노출되는 상태다. 행동 점수에는 **노출 위험** 요소가 들어가고, 그 가중치를 연출가가 조정한다. 플레이어가 관절을 자주 노리면 관절을 노출하는 행동이 덜 선택되거나, 노출 방향이 플레이어 반대쪽이 되도록 방향 전환이 먼저 선택된다. 이렇게 하면 "관절을 가리는 자세", "방향 전환" 같은 대응이 별도 규칙 없이 행동 선택에서 나온다.

### 역할별 계약 (기본값, 2026-09-23. 2026-10-05부터는 장비 프리셋의 기대 동작)

U5 플레이 기록: "멀어지면 따라오다가 가까이 가면 도망간다(우리 집에 왜 왔니)", "인형별이 아니라 군체처럼 같이 움직인다", "한두 명이 무조건 앞을 막는다". 원인은 T15 명세였다. 행동을 요소 하나씩만 정했고, 요소들이 같이 돌 때의 움직임은 따지지 않았다. 그래서 행동은 **역할별 계약**과 **금지 패턴**으로 정하고, 금지 패턴은 수치 기준의 테스트로 검사한다. Unity 플레이 전에 Core 시뮬레이션 궤적으로 먼저 확인한다(`dotnet run --project src/Core.Sim -- --puppets <approach|circle|retreat|healer>`).

**이 표는 고정 규칙이 아니라 기본값이다.** 역할마다 행동 가중치 표를 두고, 연출가는 대응마다 **역할별 가중치**를 바꾼다(예: 근접 의존이 높은 플레이어에게 Attacker의 거리 유지를 켜서 치고 빠지게 한다, 힐러를 노리지 않는 파티에게 Healer를 앞으로 끌어낸다). 개체 상태가 바뀌면 배역과 반대되는 행동도 나온다(아래 "인형 상태").

거리 기준: 위협 반경 ThreatRadius(기본 6m), 공격 거리 AttackRange(기본 2m).

| 역할 | 평소 (위협 반경 밖) | 사람이 위협 반경 안 | 공격 거리 안 | 대응에 따라 강해지는 것 |
|---|---|---|---|---|
| Guard | 진형 앞자리를 지킨다 | **맞선다**: 다가간다. 물러나지 않는다 | 공격 | 힐러 보호: **한 명만** 힐러 위협자를 따라다니며 막는다 |
| Attacker | 가장 가까운 사람에게 다가간다 | **파고든다** | 공격 | 방패 전진: 원거리 위협자를 우선 노린다 |
| Healer | 진형 뒷자리 | Guard 뒤에서 **거리를 유지한다**. 기본값에서 물러나는 건 Healer만 한다 | 거리를 벌린다 | 분산: 다른 인형과 간격을 벌린다 |

- **다가가기 점수는 가까워져도 떨어지지 않는다.** 공격 거리 밖이면 거리와 관계없이 일정하고, 공격 거리 안에 들어오면 공격이 이어받는다.
- **자리 지키기는 위협이 없을 때만 높다.** 위협 반경 안에 사람이 있으면 거의 0이다. 자리로 돌아가려다 플레이어에게서 멀어지는 일을 막는다.
- **막아서기 조건:** 힐러 위협 정보는 힐러 집중이 기준값(ThreatFactThreshold, 기본 0.35) 이상일 때만 올린다. 막아서기는 힐러 보호 대응에서 강하게 작동하고, 다른 대응에서는 약하다.
- **개체 차이:** 인형마다 행동 가중치를 시드 기반으로 조금씩(±WeightJitter, 기본 15%) 다르게 한다.

### 금지 패턴 (테스트로 검사)

둘로 나눈다. **항상 금지**는 어떤 대응·상태에서도 나오면 안 되는, 말이 안 되는 움직임이다. **기본값에서만 금지**는 이유 없이 나오면 안 되지만 대응이나 개체 상태가 이유가 되면 허용되는 움직임이다.

| 금지 패턴 | 범위 | 기준 (시나리오 10초) |
|---|---|---|
| 이유 없는 도망 | 기본값에서만 | 거리 유지를 켜지 않은 인형이 위협 반경 안의 사람에게서 **멀어지는** tick이 0 (흩어지기로 인한 옆 이동은 거리 증가 0.3m 이내 허용). 대응이 거리 유지를 켰다면, 그 인형은 정해진 거리 범위를 **일관되게** 유지해야 한다(범위를 벗어난 채 1초 넘게 있지 않음, 아래 진동 기준도 적용). 몸·장력·결이 이유가 되는 도망은 "인형 상태"의 조건으로 검사한다 |
| 진동 | 항상 | 인형 하나의 행동 전환이 3초마다 3회 이하. 다가가기 ↔ 자리 지키기, 다가가기 ↔ 거리 유지 왕복이 없음 |
| 군체 동기화 | 항상 | 행동이 바뀐 tick 중 인형 둘 이상이 **같은 tick에** 바뀐 비율 20% 미만. **의도된 협동은 세지 않는다:** 블랙보드 예약(예: 포위 각도, 막아서기)이나 연출가의 명령(합동 공격, 교전 중 지시가 생기면 그것)에 따른 동시 전환은 협동이다. 이유 없이 모두 같은 행동을 고르는 것만 군체로 센다(T16b-3a-1부터. 동시 전환마다 원인이 예약·명령인지 기록해야 구분된다) |
| 겹치기 | 항상 | 예약이 필요한 일(막아서기 등)을 두 명 이상이 동시에 하지 않음 |
| 막아서기 과다 | 기본값에서만 | 힐러 위협 사실이 없을 때 막아서기 비율 20% 미만(T17부터. 예전 기준 "힐러 보호가 아닌 대응에서"는 개인 위협을 대응과 독립적으로 반영하면서 바뀌었다) |
| 무반응 | 항상 | 사람이 공격 거리 안에 1초 넘게 있으면 인형 중 하나는 공격. **Core 테스트는 행동 상태(attack 선택)만 본다.** 실제 공격이 반복해서 나가는지는 Unity에서 따로 확인한다(U5f 참고) |
| 배역 수행 불능 시 정지 | 항상 | 배역의 우선 행동을 할 능력이 없는 개체도 대체 행동(마지막은 기본 행동) 중 하나를 고른다. 위협 반경 안에 사람이 있는데 비틀거림·그로기가 아닌 상태로 1초 넘게 이동도 공격도 하지 않으면 실패(2026-10-05) |
| 역할 고착 (후보) | 항상 | 몸이나 장력이 크게 바뀌었는데도 모든 개체가 배역 기본값에서 한 번도 벗어나지 않음. 기준 수치는 첫 구현 뒤에 정한다 |

## 인형 상태 (2026-09-23)

T15r 플레이 기록: 방해 자체는 동작한다. 하지만 "인형들을 지나쳐 가면 내 뒤에 서서 멀뚱멀뚱 있는다", "힐러가 나를 쫓는 Guard 뒤에 붙어 같이 끌려온다". 역할 계약만으로는 인형이 역할에 갇힌다.

"뒤에서 멀뚱히 서 있음"의 원인(코드 확인, 2026-09-23). 셋이 겹쳤다.

1. **공격이 한 번만 나간다.** Unity(`PrototypeJointAttack.Brain.cs`)는 행동이 attack으로 **바뀔 때만** 바닥 경고를 만든다. 사람이 공격 거리 안에 머무르면 attack이 계속 선택되므로 첫 공격 뒤로는 서 있기만 한다. 들어갈 때 쿨다운 중이었으면 한 번도 안 친다. → U5f
2. **대상을 보지 않는다.** Core는 방향을 이동 방향으로만 정한다. attack은 제자리이므로, 사람이 지나쳐 가면 인형은 등을 보인 채 서 있다. → U5f
3. **위협 반경 밖이면 Guard가 자리로 돌아간다.** Guard의 hold 가중치(0.1 × 3 = 0.3)가 approach(0.2)보다 높아서, 사람이 6m 밖으로 벗어나면 진형 자리로 돌아가 선다. 원거리 플레이어를 상대로는 Guard가 교전하지 않는다. → T16b(상황: 최근 교전)

요소를 하나씩 더하는 대신 개체의 상태 구조를 먼저 세운다. 도망, 반항, 웅크림 같은 행동은 하나씩 정의하지 않고, 아래 층들이 겹쳐서 나오는 **결과**로 만든다.

### 적의 두 종류

공연에는 인형과 **인형화된 사람**이 함께 나온다(`docs/worldbuilding.md` "강제되는 공연"). 둘은 같은 행동 선택 구조를 쓰고, 실이 끊겼을 때와 쓰러질 때가 다르다.

| | 인형 | 인형화된 사람 |
|---|---|---|
| 실이 끊기면 (장력 0) | **풀려난다.** 전투에서 빠지고 회수할 수 있다 | **잠깐 그로기** 뒤 연출가가 다시 연결한다 |
| 체력이 0이 되면 | 부서진다. 부품만 남는다 | **인형화가 풀리고 그 자리에 쓰러진다(구출).** 충돌과 공격 대상에서 빠지고, 그 교전에서 다시 연결되지 않는다. 교전이 끝나면 깨어나 대피한다 |
| 진행 조건 | 부수거나 풀어 준다 | 체력을 전부 깎아야 한다 |
| 실은 (아래 "실 회수") | 부수면 연출가에게 돌아가고, 풀어 주면 사라진다 | 구출하면 일부만 돌아간다 |

같은 카운터라도 대상에 따라 의미가 달라진다. 누구에게 무엇을 쓸지가 판단거리가 된다.

### 층

```
행동 점수 = 몸과 장비가 허락하는 행동 안에서
            [실 장력 × (배역 × 연출가 의도) × 결의 수행 방식]
          + [(1 − 실 장력) × 결의 끌림]
          + 상황(공간, 주변 개체, 최근에 겪은 일)   (× 개체 차이)
```

결은 두 곳에 쓰인다. **수행 방식**은 장력과 관계없이 항상 적용된다. 실이 팽팽해도 대담한 Guard는 더 가까이, 신중한 Guard는 한 발 뒤에서 막아선다. **끌림**은 장력이 낮을 때 배역을 벗어나는 방향이다. 결이 수행 방식에도 쓰이지 않으면, 실이 멀쩡한 교전 초반에는 개체 차이가 ±WeightJitter만 남아 다양성이 없다.

| 층 | 무엇 | 바뀌는 때 | 보이는 단서 |
|---|---|---|---|
| **몸과 장비** | 체력, 자세, 파츠 상태, 장착한 장비와 그 능력 태그. **할 수 있는 것**과 실행 속도를 정한다. 다른 층은 이 안에서만 고른다 | 교전 중 | 비틀거림, 느려짐, 자세 무너짐, 든 무기 |
| **결** | 개체마다 고유한 성향. **하고 싶은 것**을 정한다 | 거의 고정. 겪은 일로 조금씩 움직인다 | 대기 동작, 실이 느슨할 때의 행동 |
| **실** | 개체마다 따로인 장력. 배역과 결 중 어느 쪽이 행동을 쥐는지 정한다 | 교전 중 | 실이 팽팽한지 늘어졌는지 |
| **배역** | 연출가가 이번 교전에 준 지시(Guard / Attacker / Healer 등). 인형의 속성이 아니다(위 "능력 기반 행동") | 교전 사이 | 진형, 행동 |
| **연출가** | 의도(교전 사이) + 조율(교전 중 장력 배분) | 둘 다 | 인형사의 명령, 실을 다시 조이는 동작 |

- **상태 항목은 열린 모음이다.** 관찰 경향과 같은 방식으로 식별자 → 값의 모음으로 두고, 새 항목을 더해도 행동 선택 구조가 바뀌지 않게 한다.
- **배역이 행동을 막지 않는다.** 능력이 허락하는 행동이라면, 장력이 낮거나 몸이 무너질 때 배역과 반대되는 행동이 나올 수 있어야 한다. 앞을 맡은 인형이 도망갈 수도 있고, 회복을 맡은 인형이 앞으로 나설 수도 있다. 다만 능력이 없는 행동은 어떤 경우에도 나오지 않는다.

### 결

- **출신으로 정하지 않는다.** 출신(짐꾼, 수리공 등)을 행동 범주로 쓰면 인형이 다시 고정된다.
- **연속적인 축 몇 개로 둔다.** 범주가 아니라 축 위의 값(-1 ~ 1)이다. 첫 축은 **대담 ↔ 신중**(막아서는 거리, 물러나는 시점)과 **혼자 ↔ 무리**(아군이 쓰러지거나 흩어질 때 모이는가 흩어지는가)다. 축은 열린 모음이라 뒤에 더한다(후보: 집착 ↔ 변덕). 값은 시드로 정하고, 겪은 일에 따라 조금씩 움직인다. 인형극이 반복으로 역할을 가르친다는 설정처럼, 결은 반복으로 굳은 버릇이다.
- **장비와 독립이다.** 같은 창을 든 둘이 결 때문에 다르게 싸우고, 같은 결이 무기를 바꾸면 또 다르게 싸운다. 다양성은 곱으로 늘어난다.
- **인형화된 사람의 결은 그 사람 자신의 의지다.** 그로기 순간에 그 사람다운 행동이 잠깐 비치는 식의 단서가 가능하다(예시).

### 실 장력

- 개체마다 따로 가진다. 0 ~ 1.
- 내리는 것 후보: 연결 실 파츠 피해(아래 "파츠별 행동 결과"의 "통제 안정성"이 곧 장력이다), 교란 공격, 실 카운터. 올리는 것: 연출가의 조율.
- 장력이 낮을수록 결이 행동을 쥔다. 대상이 바뀌기 전에는 전조를 둔다(열린 질문 "장력 저하는 어떻게 읽히게 하나").

### 상황

공식의 "상황"은 지금 벌어지는 일에 대한 개체의 반응이다. T15r의 "지나치면 뒤에서 대기"처럼, 개체가 공간 관계를 모르면 배역과 결이 있어도 멀뚱히 선다. 최소 항목(열린 모음의 첫 항목):

| 항목 | 예 |
|---|---|
| 공간 | 위협의 방향(앞/옆/뒤), 사람이 나를 지나쳐 갔는지, 포위되었는지, 아군과의 거리, **보호할 아군(힐러 등)과 위협 사이의 거리** |
| 주변 개체 | 아군이 쓰러짐, 가까운 아군이 하는 행동, 막아서기 예약을 누가 가졌는지 |
| 최근에 겪은 일 | 연속 피격, 방금 실이 끊겼다 이어짐, 방금 대상을 놓침 |

상황은 결과 곱해진다. 같은 "아군이 쓰러짐"에도 무리 쪽 결은 모이고, 혼자 쪽 결은 흩어진다.

**힐러 보호는 교전 중 반응이다.** 앞을 제끼고 힐러에게 가도 아무도 지키지 않는 문제(T15r Play)는 막아서기가 교전 사이의 관찰(힐러 위협 사실)로만 켜지기 때문이다. 사람이 보호할 아군에게 가까워지면 교전 중에도 Guard 한 명이 막아서기로 반응한다(원칙 3의 "상황에 대한 반응"). 힐러 보호 대응(GuardHealer)은 이 반응을 더 일찍, 더 강하게 만든다. 결이 반응을 가른다: 무리 쪽 Guard는 돌아와 지키고, 혼자 쪽 Guard는 상대하던 사람을 계속 쫓는다.

**힐러에게는 회복 행동이 필요하다.** 지금 힐러는 이름만 힐러다(회복 후보가 없다). 그래서 힐러를 지킬 이유도, 못 지켰을 때 잃는 것도 없다. 회복만 넣으면 힐러가 늘 첫 표적이 되고, 보호만 넣으면 지킬 이유가 없으므로 **회복 행동과 보호 반응은 같은 run에 넣는다**(T16b).

### 연출가의 조율 예산

- 연출가가 교전 중에 다시 조일 수 있는 실은 한정되어 있다. **한 개체의 실을 조이는 동안 다른 개체의 실은 풀린 채 남는다.**
- **연출가도 완벽하지 않다.** 여러 개체를 동시에 흔들면 연출가가 감당하지 못하고 파티가 제각각이 된다. 이것이 플레이어의 전략이 된다.
- **기본은 실이 팽팽하다.** 벗어남은 플레이어가 흔든 만큼만 생긴다. 인형이 스스로 흩어지지 않으므로, 교전 중 변화가 너무 많아 읽을 수 없게 되는 일을 조율 예산이 막는다(`docs/worldbuilding.md` "적응형 전투의 피로도 원칙").
- 조이는 동작은 화면에서 보여야 한다(누구의 실을 붙잡는지). 수치와 표현은 첫 구현 뒤에 정한다.

### 실 회수

개체가 쓰러지면 그 개체에 걸려 있던 실이 어떻게 되는지는 **쓰러뜨린 방법**에 달려 있다.

| 쓰러뜨린 방법 | 실 | 조율 예산 |
|---|---|---|
| 부숨 (인형 체력 0, Broken) | 끊기지 않았으니 연출가에게 돌아간다 | + 한 줄 몫 |
| 풀어 줌 (인형 장력 0, Released) | 플레이어가 끊었으니 사라진다 | 변화 없음 |
| 구출 (인형화된 사람 체력 0, Downed) | 사람의 의지와 엉켜 일부만 돌아간다 | + 한 줄 몫 × 회수 비율(1 미만) |

- **인형 수는 줄어도 남은 인형은 더 촘촘하게 통제된다.** 개체 하나가 강해지는 게 아니라 다시 조이는 속도가 빨라진다. "잘할수록 적이 일방적으로 강해지지 않는다"를 지킨다.
- **상한을 둔다.** 마지막 인형이 지나치게 단단해져 교전 끝이 늘어지지 않게, 늘어난 예산은 기본의 몇 배까지만 허용한다.
- **돌아가는 실은 보여야 한다.** 실이 연출가 쪽으로 감겨 들어가는 연출 등. 플레이어가 "부쉈더니 남은 인형이 빨리 추스른다"를 이해할 수 있어야 한다.
- **구출 순서의 딜레마.** 돌아온 실은 남은 개체에게 쓰이므로, 효율만 보면 인형화된 사람은 마지막에 구출하는 게 유리하다. 사람의 실은 일부만 돌아가게 해서 이 유인을 약하게 둔다. "빨리 구할 것인가, 효율적으로 싸울 것인가"는 선택으로 남기되, 한쪽이 늘 정답이 되지 않게 회수 비율로 조정한다. 먼저 구하는 쪽의 이득을 더 주는 방법은 열린 질문이다.
- **나중(T16c 이후) 후보: 돌아온 실을 남은 인형에 하나 더 건다.** 두 줄 인형은 장력이 잘 떨어지지 않는 대신 연결부가 하나 늘어 카운터 기회도 는다. 카운터 규칙과 얽히므로 파츠 뒤에 정한다.

### 연출가마다 다르다

연출가는 모두 같은 인물이 아니다. 연출가에게도 **결**이 있고, 두 곳에 드러난다.

- **조율 방식:** 예산이 모자랄 때 누구의 실을 먼저 조이는가. 예: 첫 연출가 "무대감독"은 모두를 정확한 위치에 세우면 사고를 막을 수 있다고 믿으므로, 자리를 벗어난 개체부터 조인다. 다른 연출가는 공격하는 개체부터, 또는 가장 아끼는 배역부터 조일 수 있다(예시).
- **대응 선호:** 같은 관찰에서 어떤 대응을 고르는가. 무대감독은 자리 고정, 밀어내기, 정교한 진형과 합동 공격을 선호한다(`docs/worldbuilding.md` "버들막").

연출가를 바꾸는 것만으로 같은 인형들이 다르게 싸운다. 다양성이 개체, 파티, 연출가 세 층에서 곱해진다.

### 다양성의 조건

- **무작위와 다르다.** 모든 벗어남에는 보이는 원인이 있어야 한다(원칙 4). 플레이어가 "왜 저러지?"를 행동과 전조로 추론할 수 있으면 다양성이고, 없으면 잡음이다. 테스트: 배역에서 벗어난 행동마다 그 직전에 몸·장력·상황 중 하나의 변화가 기록되어 있다.
- **결정론은 유지한다.** 상태와 시드가 같으면 같은 결과가 나온다.
- **금지 패턴은 그대로 적용한다.** "이유 없는 도망"의 "이유"에 몸·장력·결이 들어간다.
- **다양성은 재서 확인한다.** 금지 패턴은 "나오면 안 되는 것"이고, 다양성은 "나와야 하는 것"이라 따로 잰다. `Core.Sim`으로 같은 시나리오를 시드(= 결 조합) 여러 개로 돌려 행동 분포와 궤적이 얼마나 갈리는지 출력한다. 기준: 같은 배역이라도 결이 다르면 행동 순서가 갈리고, 동시에 금지 패턴은 모든 시드에서 통과한다. 수치는 첫 구현 뒤에 정한다.

### 생활과의 연결 (설계 여지만, 구현 범위 아님)

생활 콘텐츠는 초기 구현 범위가 아니다(`docs/worldbuilding.md` "생활과 마을"). 지금은 AI 쪽에서 막히지 않게만 한다.

- **인형은 정체성을 가진 개체다.** 교전마다 찍어 내는 유닛이 아니라 id, 결, 겉모습을 가진다. 결은 전투 밖에서도 읽을 수 있는 데이터로 둔다.
- 풀려난 인형은 회수해 마을에서 생활용으로 개조할 수 있다. 부순 인형은 부품만 남는다. 회수는 추가 보상이며 강제하지 않는다(피로도 원칙).
- 마을에서 본 인형의 결은 전투에서 읽는 단서가 된다. UI 없이 세계 안의 단서로 전달한다는 원칙과 맞는다.

## 공격 특성과 파츠 연동 (초안)

게임 규칙(공격 특성 다섯 가지, 파츠 네 종류, 일반 공격·파츠 기회 공격·실 카운터의 구분)은 `docs/planning.md`의 "공격 속성과 파츠"에 둔다. 여기에는 AI가 그것을 어떻게 관찰하고 대응하는지만 적는다. 관찰 원칙은 위 "관찰", 노출은 위 "행동과 노출"을 따른다.

**대응 예시:**

| 관찰된 플레이어 행동 | 인형의 대응 후보 | 행동 선택에서의 구현 |
|---|---|---|
| 관절 타격 반복 | 관절을 가리는 자세, 보호 인형 배치, 방향 전환 | 관절을 노출하는 행동의 노출 위험 가중치 ↑, 막아서기 ↑ |
| 연결 실 집중 | 실의 노출 시간을 줄이고 연결부를 분산 | 실 노출이 긴 행동 ↓, 거리 벌리기 ↑ |
| 신호 장치 교란 반복 | 합동 공격 명령을 나누거나 가짜 신호를 섞음 | 합동 공격 계획 쪽 변경(행동 선택 밖) |
| 관통 공격 비율이 높음 | 전방 방어보다 측면 압박과 접근 행동을 강화 | 측면으로 돌아 접근 ↑ |

파츠 기회 공격은 교전 중 행동 선택에 영향을 주고, 실 카운터는 기존처럼 명확한 카운터 창에서 처리한다. 정확한 조준을 해야만 진행되는 구조는 쓰지 않는다.

### 파츠별 행동 결과

파츠 피해는 단순한 피해량 보정으로 끝내지 않는다. 몸체는 일반 피해를 담당하고, 파츠는 개체 상태의 다른 층을 바꾼다. 초기에는 파츠마다 대표 행동 변화 하나를 사용한다. AI는 플레이어가 파츠 기회 공격으로 어떤 행동 변화를 반복해서 유도하는지 관찰하고, 그 행동을 보호하거나 방향을 바꾸는 가중치를 조정한다.

| 파츠 | 걸리는 곳 | 구현 방향 |
|---|---|---|
| 관절 | **몸**: 행동의 실행(이동·회전·준비 속도, 준비 취소) | 점수보다 실행에 먼저 반영한다. 느려지거나 취소되는 것은 눈에 보이지만, 점수가 낮아져 덜 고르는 것은 잘 보이지 않는다 |
| 연결 실 | **실 장력**: 통제 안정성과 대상 우선순위 | 대상이 바뀌기 전에 보이는 전조를 둔다. 카운터의 Thread 연결부와는 별개다 |
| 신호 장치 | **합동 공격 계획**(`JointAttackPlan`의 순서·범위·대상) | 행동 선택기가 아니라 계획 쪽을 바꾼다. 카운터의 Signal 연결부와는 별개다 |

**코드 이름:** 공격 특성의 절단·교란과 카운터의 Cut·Disrupt는 다른 개념이다. 코드에서는 공격 특성을 `AttackTrait`(`Slash`, `Blunt`, `Pierce`, `Press`, `Jam`)으로, 카운터는 기존 `InterferenceMethod`(`Cut`, `Shoot`, `Disrupt`)로 둔다.

## 장비와 행동 패턴 연동 (초안)

장비 구조(무기 / 방어구 / 무대 도구)는 `docs/planning.md`의 "장비 구조"에 둔다. AI 쪽 원칙만 적는다.

- **연출가는 장비를 직접 읽지 않는다.** 무기 이름이나 방어구 세트를 보고 전용 카운터를 고르지 않고, 장비가 만들어 낸 실제 공격 특성·이동·카운터 방식의 반복을 관찰한다.
- 예: 관절 타격이 반복되면 연출가는 인형의 관절 보호·방향 전환 가중치를 높인다. 이 대응은 관절을 영구히 무효화하지 않고, 보호에 쓴 인형의 위치나 다른 파츠의 노출 같은 교환을 만든다.
- **인형도 플레이어와 같은 장비를 장착한다.** 장비 데이터는 공유하고 판단 계층은 편마다 다르다(위 "능력 기반 행동"). 인형의 장비는 할 수 있는 행동과 사거리를 정하고, 성향(결)과는 독립이다.
- **봇에게는 장비가 판단 기준이다.** 연출가와 달리 봇은 자기 장비를 읽는다(아래 "아군 봇").
- 세트 효과와 장식 슬롯은 현재 AI 판단 범위에 포함하지 않는다.

## 아군 봇 (설계만, 구현은 뒤)

- 같은 행동 선택 구조를 쓰고, 편만 플레이어 쪽이다.
- 자유 빌드이므로 봇은 **자기 장비가 할 수 있는 일**과 **파티에 부족한 일**을 보고 행동 가중치를 정한다. 무기는 공격 특성과 노릴 파츠를, 방어구는 버틸 수 있는 위치(예: 채널링을 오래 유지할 수 있으면 위험한 자리)를 정한다. 상세 수치는 공격 속성·파츠가 정해진 뒤에 적는다.
- **무대 도구가 카운터 분담을 정한다.** 연결부 예약에서 봇은 자기 무대 도구가 강화하는 방식의 연결부를 먼저 맡는다. 예: Disrupt 도구를 든 봇이 Signal을 우선 예약한다. 기본 세 방식은 모두 쓸 수 있으므로, 맡을 사람이 없는 연결부는 도구와 관계없이 가까운 봇이 맡는다.
- **카운터에 참여한다.** 블랙보드 예약으로 연결부를 나눠 맡아, 사람과 봇이 같은 연결부를 동시에 노리지 않게 한다. 사람이 먼저 노리는 연결부는 양보한다.
- **완벽하지 않다.** 반응 지연과 실수 확률을 둬서 평범한 동료 수준으로 맞춘다. 수치는 설정으로 둔다.
- 연출가의 관찰 대상이 아니다.

## 시뮬레이션 플레이어와 쌍방 학습 (2026-10-05)

혼자 하는 Play로는 교전 몇 번, 전략 한두 개밖에 못 본다. 파티(4~5인)에서의 개인별 대응은 혼자서는 아예 볼 수 없다. 그래서 플레이어 쪽도 봇으로 두고, 연출가와 서로 배우게 한다. 목표는 게임의 핵심 경험인 **"얘가 이렇게 하는구나, 그럼 나는 이렇게"를 봇끼리 재현**하는 것이다.

**자동화가 대신하지 못하는 것:** 재미와 사람 눈의 가독성. 봇은 Play를 대체하지 않고, Play 전에 거른다.

### 학습은 세기와 규칙으로 한다

**학습된 모델(신경망, 강화학습)을 쓰지 않는다.** 연출가는 관찰 비율을 세고 이동 평균으로 기억한다(지금 방식). 시뮬레이션 플레이어는 "이 단서가 보였을 때 이 선택을 했더니 결과가 어땠다"를 세고 잘된 쪽을 더 자주 고른다(밴딧). 이유: 왜 그렇게 했는지 숫자로 추적되고(원칙 4), 결정론적이라 테스트로 고정되고, 서버에서 가볍고, 배우는 속도·잊는 속도·변화 폭을 설정으로 조절할 수 있다. 세계관 문서의 "머신러닝이 필수인 것은 아니다"와 같다. 한계는 미리 정한 선택지 안에서만 고른다는 것인데, 테스트용으로는 사람이 할 법한 범위 안에서 검증한다는 장점이 된다.

### 시뮬레이션 플레이어는 아군 봇과 다르다

| | 시뮬레이션 플레이어 | 아군 봇 |
|---|---|---|
| 어디에 있나 | `Core.Sim` 안에서만 | 실제 게임 |
| 연출가에게는 | **사람으로 보인다**(관찰 대상) | 관찰에서 빠진다("정한 것") |
| 목적 | 사람을 흉내 내 AI를 검증 | 모자란 파티를 채움 |

### 전략 원형이 아니라 장비 조합 + 성향 값

고정된 "힐러 저격 봇"을 만들지 않는다. 장비 조합(위 "능력 기반 행동"과 같은 데이터)과 성향 값(공격 성향, 위험 회피, 대상 선호 등)으로 만들고, 행동은 조합에서 나온다. 예: 원거리 무기 + 높은 공격 성향 + 낮은 위험 회피 → 후방 대상을 자주 노린다.

### 보이는 것만 보고 배운다

시뮬레이션 플레이어의 입력은 **화면에 보이는 단서**로 제한한다: 진형 모양, 인형 사이 간격, 누가 누구를 따라다니는지, 회복 담당 앞에 누가 서는지, 장비. 연출가의 내부 상태(무대 구성 이름, 의도 배율, 기억 값)는 보지 않는다. 그래서 **보이는 단서만으로 봇이 대응을 바꾸지 못하면, 그 적응은 사람에게도 잘 안 읽힐 가능성이 크다.** 가독성의 일부를 숫자로 볼 수 있다.

### 사람답게 바뀐다

연출가가 교전 사이에만 바뀌고 변화 폭에 상한이 있듯이, 시뮬레이션 플레이어도 교전 사이에만 선택을 바꾸고, 한 번에 크게 뒤집지 않고, 탐색은 조금만 한다.

### 보상

피해·처치 결과는 T16c~d 뒤에 생긴다. 그 전에는 지금 있는 결과로 대신한다: 카운터 성공, 노린 대상에 공격이 닿았는지(막혔는지).

### 쌍방 학습에서 볼 것

| 현상 | 의미 | 지표 |
|---|---|---|
| 순환(힐러 저격 → 호위 → 광역 → 분산 → …) | 원하는 모습. 서로 읽고 바꾼다 | 선택과 무대 구성의 전이가 반복되는지 |
| 수렴(한 선택으로 굳음) | 정답 전략이 있다. 밸런스 문제 | 한 선택의 점유율 |
| 꼼수(사람이라면 안 할 행동으로 이김) | 시뮬레이터나 AI의 허점 | 결과가 지나치게 치우친 선택(사람이 확인) |
| 반응 지연(연출가가 바뀐 걸 늦게 알아챔) | 단서가 약하다(가독성) | 연출가가 바뀐 뒤 선택이 바뀌기까지 교전 수 |

### 자유도와 연출가를 재는 지표

자유도를 감으로 판단하지 않고 리포트로 잰다.

| 지표 | 무엇을 보나 | 언제부터 |
|---|---|---|
| 해법의 수 | 하나의 목표를 몇 가지 장비 조합으로 해결할 수 있나 | T18a |
| 지배적인 태그 | 특정 능력 태그가 모든 상황에서 최적이 되나 | T18b |
| 적응 뒤 남는 선택 | 연출가의 대응 뒤에도 기존 빌드에 유효한 선택이 최소 하나 남나 | T16d 뒤(결과 필요) |
| 배역 수행 불능 시 정지 | 능력이 없는 배역이 나왔을 때 행동이 멈추지 않나(금지 패턴과 같다) | T16b-2 |
| 설명 가능성 | 벗어난 행동마다 장비·배역·결·실·상황 중 원인이 기록되어 있나 | T16b-3 |
| 배역 목표 달성 | 배역의 목표(예: 회복 담당의 생존)가 교전 동안 얼마나 지켜졌나 | T18a |
| **연출가 끄기 비교** | 같은 시드로 연출가의 배역·적응·조율을 끈 판과 켠 판의 행동 분포·결과 차이(위 "연출가: 판을 짜는 존재") | T18a |

배치로 시드 여러 개를 돌려 금지 패턴, 다양성, 위 지표를 리포트로 낸다. 이 리포트는 jevcode run의 검증 근거로도 쓴다.

## 열린 질문

**인형 상태**

- 연출가의 결은 인형의 결과 같은 축인가.
- 조율 예산의 수치와 보이는 방식.
- **장력 저하는 어떻게 읽히게 하나?** "통제 안정성과 대상 우선순위가 흔들림"은 화면에서 무작위로 움직이는 것처럼 보이기 쉽다. 대상을 바꾸기 전에 보이는 전조가 필요하다(예: 실이 늘어지며 잠깐 비틀거린 뒤 대상을 바꾼다). 파츠 첫 검증에서 가장 먼저 확인할 항목이다.
- 인형화된 사람의 그로기 길이와 재연결 연출.
- **먼저 구하는 쪽의 이득(추후).** 후보: 인형화가 오래갈수록 연출가가 그 사람의 결을 배역으로 덮어쓴다. 늦게 구하면 그 사람이 달라져 있거나 보상이 줄어든다. 주제("각본이 사람의 선택을 지운다")와 가장 잘 맞지만 설계가 크다. 사람 실의 회수 비율만으로 딜레마가 충분한지 Play로 먼저 본다.
- 돌아온 실의 표현(연출가 쪽으로 감겨 들어가는 연출 등).
- **인형화된 사람은 싸우기 전에 구별되는가?** 실을 끊을지 체력을 깎을지 판단해야 하므로, 교전 전에 보여야 한다.
- **인형화된 사람을 치는 느낌.** 체력을 0으로 만드는 것이 공격이 아니라 "버틸 힘을 꺾는" 것으로 느껴져야 한다. 타격감과 소리를 인형과 다르게 한다.
- 인형이 쓰러지는 조건. 윤곽은 잡혔다(몸체 체력 + 자세 게이지, `docs/planning.md`). 수치와 조건은 T16에서 정한다.
- 회수한 인형과 아군 봇의 관계. "플레이어는 인형을 부리는 소환사가 아니다"(`docs/worldbuilding.md`)와 부딪히지 않아야 한다.

**능력과 연출가 (2026-10-05)**

- **교전 중 지시.** 연출가가 교전 중에 "모여라", "힐러를 감싸라" 같은 지시를 낼 수 있게 할 것인가. 낸다면 보이는 신호와 횟수 제한이 필요하다(위 "시야는 나뉜다").

- **능력 태그의 조합 효과.** 예: `Protect + Heal` → 보호하면서 회복, `Block + Disrupt` → 막으면서 교란. 조합 수가 폭발하고 읽힘이 어려워지므로 미룬다. T18에서 "단순 합으로는 부족하다"는 근거가 나오면 그때 2~3개만 직접 정의한다. 공격 특성(`Pierce`, `Press`)은 능력 태그가 아니므로 같은 층에 섞지 않는다.
- **배역 충돌.** 한 개체에 보호와 공격을 동시에 요구하면 결에 따라 고르게 할 것인가. 지금은 개체당 배역 하나로 피하고, "잠깐 공격 후 회복" 같은 판단이 계약 + 결 + 상황에서 저절로 나오는지 먼저 본다.
- **장비 배분의 규칙.** 연출가가 관문 사이에 무엇을 바꿀 수 있나(장비만 / 인형 교체까지), 바꿀 수 있는 양, 무대 구성(진형·합동 공격)과의 관계, 정찰에서 어떻게 보이나.
- **연출가 끄기 비교의 기준값.** "충분히 다르다"와 "너무 다르다"의 경계를 T18a 첫 리포트를 보고 정한다.

**전투 흐름**

- 합동 공격 전조와 카운터 창 동안 인형은 무엇을 하나. 제자리를 지키는가, 노출된 연결부를 플레이어 반대쪽으로 돌리는가(연결부 찾기 재미를 키울 수 있음)? 프로토타입은 임시로 이 동안에도 PuppetBrain을 계속 진행한다.
- 교전 한 번에 인형 몇 개를 쓰나. 지금은 4개 고정이다.
- **미끼는 어떻게 읽히게 하나?** 정직하지 않은 노출은 "읽고 대응하는" 재미를 해칠 수 있다. 미끼 노출에는 진짜 노출과 구별할 수 있는 신호(예: 다른 인형의 준비 동작이 함께 보임)가 있어야 한다. 신호 없이 속이는 미끼는 쓰지 않는다.

**기억**

- 원정을 넘는 플레이어 식별자를 어디서 받나(서버 계정 id 등). 프로토타입에서는 원정이 하나라 문제가 드러나지 않는다.
- CarryOverRatio와 MaxIntentShiftPerEncounter의 값. Play로 정한다.
