인형의 판단 주기 기본값을 30 tick에서 10 tick으로 바꾼다. 근거: S2(수치 탐색)에서 주기 10만 두 지속 보너스(0.02, 0.05) 모두 금지 패턴 0, 27조합 계약 실패 0, 끊김 0이었고, U7로 Play한 결과 "굼뜸이 확실히 줄고, 리듬이 괜찮아지고, 덜 떤다"(2026-11-08 사용자 판단).
**바꾸는 것은 이 기본값 하나다.** 다른 기본값(persistenceBonus 0.02 등), 행동 규칙, 점수 계산, 재평가 시점을 엇갈리는 방식(인형 순번 × 간격 / 인형 수)은 바꾸지 않는다. Unity 코드는 바꾸지 않는다.

1) src/Core/PuppetSettings.cs: 공개 생성자 두 개의 reevaluationIntervalTicks 기본값을 30에서 10으로 바꾼다. 이 값이 임의로 정한 값이라는 표시(주석)가 있으면 근거를 'S2 탐색 + U7 Play, 2026-11-08'로 고친다. src/Core의 다른 파일은 바꾸지 않는다.
2) 문서: src/Core.Sim/README.md나 코드 주석에 판단 주기 기본값 30이 적혀 있으면 10으로 고친다. docs/ 아래 설계 문서는 바꾸지 않는다(사람이 기록한다).
3) 궤적 해시: 기본 설정으로 도는 해시 테스트(DuoSimulationTests.LegacySevenTrajectoriesHaveReviewedHashes, InterceptRegressionTests.NonInterceptTrajectoryHasReviewedHash, TargetSelectionTests.DuoTrajectoriesHaveReviewedHashes 등)는 판단 주기가 바뀌므로 해시를 갱신한다. 테스트의 시나리오, 설정, 검사 방식은 바꾸지 않고 기대 해시 문자열만 바꾼다. **reevaluationIntervalTicks를 명시한 테스트는 해시도 결과도 바뀌면 안 된다.** 바뀌면 갱신하지 말고 원인을 보고한다.
   갱신한 해시마다 근거 표에 시나리오 이름과, 그 시나리오를 `dotnet run --project src/Core.Sim -- --puppets <시나리오>`(필요한 옵션 포함)로 이 run 전과 후에 돌린 금지 패턴 지표(도망 tick, 최대 행동 전환, 동시 전환 비율, 막아서기 인원 최대, 무반응)와 막아서기 품질을 전후로 적는다.
4) 멈출 조건: 아래 중 하나라도 나오면 해시를 갱신하지 말고 멈춘 뒤 마지막 메시지에 시나리오와 지표를 보고한다. 테스트를 고쳐서 통과시키지 않는다.
   - 금지 패턴 테스트가 하나라도 실패한다(어느 시나리오, 어느 패턴인지 적는다).
   - 막아서기 품질이 healer 80.0%, orbit 100.0%보다 낮아진다.
   - duo, duo-swap mixed의 몰림 비율이 15.3%보다 커진다(값을 보고한다. 이 경우만은 멈추지 않고 보고로 끝낸다).
5) 탐색 기준선: `dotnet run --project src/Core.Sim -- --sweep PuppetSettings.reevaluationIntervalTicks=10,15,20,30 PuppetSettings.persistenceBonus=0.02,0.05`을 실행해 출력 전체를 마지막 메시지에 붙인다. baseline 행은 이제 주기 10이다.
수치는 설정 타입에 이미 있으므로 새 설정을 만들지 않는다. 규칙 코어 테스트(dotnet test tests/Core.Tests --no-restore -m:1)는 모두 통과해야 한다.
사람이 할 일에 다음을 적는다: 'Prototype 씬의 PrototypeBootstrap PuppetTuning 목록에 PuppetSettings.reevaluationIntervalTicks가 30으로 저장돼 있으면 새 기본값이 적용되지 않는다. 그 항목을 지우거나 10으로 바꾸고 씬을 저장한다.'
마지막 메시지에 '검증 근거' 표를 둔다: 1)~5) 각각 바꾼 파일, 근거 테스트 이름 또는 출력 줄. 그리고 갱신한 해시의 개수를 테스트별로 적는다.
