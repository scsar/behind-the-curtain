docs/ai-design.md의 '결'을 src/Core에 처음 넣는다. 이번에는 결의 데이터와 두 축(대담 ↔ 신중, 집착 ↔ 변덕)의 **수행 방식**만 넣는다. 혼자 ↔ 무리 축과 장력이 낮을 때의 끌림(waver 대체)은 이번 범위가 아니다(그 축이 반응할 상황은 T16b-3c에서 생기고, Unity에서는 아직 장력이 줄지 않는다). Unity 코드는 바꾸지 않는다. 공개 API는 유지하고 새 기능은 추가로만 넣는다.
**핵심 불변식: 결이 모두 0이면(기본) 이 run 전과 궤적이 완전히 같다.** 그래서 기존 궤적 해시 테스트의 기대 문자열을 하나도 바꾸지 않고 통과해야 한다. 해시가 바뀌면 갱신하지 말고 원인을 고치거나, 고칠 수 없으면 멈추고 보고한다.

1) 결 데이터: 인형 편 개체마다 결을 둔다. 결 = 축 id → 값(-1 ~ 1)의 모음(관찰 경향, 개체 상태와 같은 열린 모음 방식). 축 id는 한곳에 모은 상수로 둔다: `boldness`(+1 대담, -1 신중), `persistence`(+1 집착, -1 변덕). 정해지지 않은 축은 0이다.
   API: World에 결을 넣고 읽는 메서드를 더한다(예: `SetTemperament(AgentId, Temperament)`, `GetTemperament(AgentId)`. 장비(Loadout)를 다루는 방식과 비슷하게). 범위 밖(-1 미만, 1 초과), NaN, 없는 id, 인형 편이 아닌 개체는 결과값으로 거부한다(예외 아님). 결은 PuppetBrain.Create 때 읽는다(그 뒤에 바꾸면 다음 Create부터 반영. U7의 F5가 Create를 다시 부르므로 Unity에서도 동작한다).
2) 적용 방식: PuppetBrain.Create가 인형마다 PuppetActions를 만들 때, 그 개체의 결을 적용한 **설정 사본**을 넘긴다(PuppetSettings에 internal 복사 메서드를 두고, BasicActionSettings 안의 값도 함께). 결이 모두 0이면 원래 settings 객체를 그대로 넘긴다(같은 객체이므로 궤적이 같다는 것이 구조로 보장된다). PuppetBrain 자신이 쓰는 settings(판단 주기, 조율 예산 등)는 바꾸지 않는다.
3) 대담 ↔ 신중(b = boldness): 거리만 바꾼다. 행동 가중치와 점수 곡선은 바꾸지 않는다. 배율 s = TemperamentDistanceScale(기본 0.3, 임의값, 새 설정).
   - 막아서기 선분: InterceptDistance × (1 + s·b), InterceptStandOff × (1 − s·b). 대담하면 힐러에서 더 떨어져 위협 쪽으로 나가 막고, 신중하면 힐러 가까이에서 막는다.
   - 견제 대기 고리: HarassMargin × (1 − s·b). 대담하면 더 가까이서 기다린다.
   - 거리 유지 범위: KeepMin × (1 − s·b), KeepMax × (1 − s·b). 대담하면 더 가까이 머문다.
4) 집착 ↔ 변덕(p = persistence): 대상을 붙잡는 정도만 바꾼다. 배율 k = TemperamentPersistenceScale(기본 0.5, 임의값, 새 설정).
   - 대상 유지: TargetSwitchMargin_eff = 1 + (TargetSwitchMargin − 1)·(1 + k·p), TargetMinHoldTicks_eff = round(TargetMinHoldTicks·(1 + k·p)). 집착하면 덜 바꾸고, 변덕스러우면 더 쉽게 바꾼다.
   - 변덕 쪽만(p < 0): TargetScore에 압박 수 가중을 곱한다: (1 / (1 + OtherPressure))^(WhimPressureWeight·(−p)). WhimPressureWeight 기본 1(임의값, 새 설정). 덜 압박받는 사람을 더 좋아하게 되어, T16b-3a-1c에서 바뀐 견제의 "가장 덜 압박받는 사람" 성격이 변덕 쪽에서 돌아온다. p ≥ 0이면 이 항은 1이다.
   - 보이는 단서: 변덕의 대상 전환은 비틀거림(waver) 없이 바로 돌아선다. 장력 저하의 전조(비틀거린 뒤 전환)와 구별되는 것은 이것이다. 이번 run에서 전환 직전에 waver를 넣지 않는다.
5) 시뮬레이터: src/Core.Sim의 --puppets에 `--temperament <none|bold|cautious|persistent|whimsical|mixed>`를 더한다. none = 모두 0(지금과 같음). bold/cautious/persistent/whimsical = 모든 인형이 해당 축 ±1(다른 축 0). mixed = 개체 10 대담 +1, 11 신중 −1, 12 변덕 −1, 13 집착 +1(고정 배정, 무작위 아님). 시작 줄에 개체별 결을 출력한다. --sweep에도 같은 옵션이 통하게 한다(그러면 contracts27을 결 프리셋별로 볼 수 있다).
수치는 설정 타입에 두고 임의로 정한 값임을 표시한다.

테스트(불변식만):
   (a) 회귀: 기존 궤적 해시 테스트가 기대 문자열을 바꾸지 않고 통과한다. 결을 명시적으로 모두 0으로 준 경우도 같은 해시다.
   (b) 결정론: 같은 시드·결·입력이면 같은 궤적.
   (c) 거부: 범위 밖, NaN, 없는 id, 플레이어 편 개체.
   (d) 정의의 경계: 가드가 힐러 바로 옆(막아서기 선분의 힐러 쪽 끝으로 투영되는 위치)에 있는 같은 월드에서, b = +1인 가드의 막아서기 목표 지점이 b = −1인 가드보다 힐러에서 멀다(목표는 선분 위 투영점이라, 가드가 선분 가운데로 투영되면 둘이 같을 수 있으므로 이 상황으로 한정한다). b = ±1에서 견제 고리 반지름과 거리 유지 범위가 3)의 식과 같다. p = ±1에서 유효 대상 유지 tick과 배율이 4)의 식과 같다. p ≥ 0이면 압박 수 가중 항이 정확히 1이다.
   (e) 금지 패턴: 결 프리셋 bold, cautious, persistent, whimsical, mixed 각각에서 기존 27조합 계약(contracts27과 같은 검사)이 통과한다. 실패하면 테스트 기준을 바꾸지 말고, 원인이 결 적용 코드 안이면 고치고, 밖이면(예전부터 있던 문제가 드러난 것) 사유를 적어 보고한다.
보고(테스트가 아님, 실행해서 숫자로): 시나리오 healer, duo, duo-swap(mixed loadout, cast)를 --temperament none/bold/cautious/persistent/whimsical/mixed로 돌린 표. 열: 막아서기 목표의 힐러까지 평균 거리, 견제 대기 중 대상까지 평균 거리, 거리 유지 중 평균 거리, 개체별 대상 전환 횟수, 몰림 비율, 막아서기 품질(within1m. 결이 0이 아니면 측정 선분은 기본 설정 기준이라 근사임을 표에 적는다), 금지 패턴 지표. 같은 배역이 결에 따라 실제로 갈리는지가 이 표로 보여야 한다.
규칙 코어 테스트(dotnet test tests/Core.Tests --no-restore -m:1)는 모두 통과해야 한다.
마지막 메시지에 '검증 근거' 표를 둔다: 1)~5)와 (a)~(e) 각각 바꾼 파일·메서드와 테스트 이름. 그리고 위 보고 표와, 결이 0일 때 원래 settings 객체를 그대로 넘기는 코드 위치.

- [근거 표] (d) 정의의 경계와 (e) 결 프리셋별 금지 패턴의 테스트 이름이 있고 리뷰 화면 테스트 목록에도 있다
- [근거 표] 보고 표 → bold의 막아서기 거리가 cautious보다 힐러에서 멀고, whimsical의 대상 전환 횟수가 persistent보다 많다(같은 배역이 결에 따라 갈린다)
