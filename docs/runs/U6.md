프로토타입(Unity)에서 인형마다 서로 다른 장비를 주고, 연출가의 배역 배분(Core의 DirectorCasting.Assign)을 불러서, 장비가 행동을 정하고 연출가가 배역을 나누는 것이 Play에서 보이게 한다. docs/ai-design.md의 '능력 기반 행동'과 '연출가: 판을 짜는 존재'를 화면에 연결하는 run이다. src/Core는 바꾸지 않는다. 필요한 Core API가 없으면 고치지 말고 마지막 메시지의 제안 섹션에 적는다.

1) 장비 편성(라인업): PrototypeSettings에 라인업 목록을 둔다. 라인업 = 인형 네 자리(앞 왼쪽, 앞 오른쪽, 뒤 왼쪽, 뒤 오른쪽)에 줄 장비 id 목록(EquipmentCatalog.Default의 id). 교전 n은 라인업 (n - 1) % 개수를 쓴다. 기본 라인업 셋(임의로 정한 값임을 표시):
   A 기준(예전과 같음): [weapon.melee, armor.shield] / [weapon.melee, armor.shield] / [weapon.melee] / [weapon.short, tool.mender]
   B 섞음: [weapon.melee, armor.heavyShield] / [weapon.melee] / [weapon.spear] / [weapon.short, tool.mender]
   C 방패 없음: [weapon.melee] / [weapon.spear] / [weapon.bow] / [weapon.short, tool.mender]
   인형을 World에 넣을 때 Core의 장비 지정 오버로드(World.Add(agent, initialState, loadout) 또는 AddWithLoadout)로 Loadout.Create(라인업의 id)를 준다. Loadout.Create가 실패하면 지금의 BrainFailure처럼 이유를 남기고 멈춘다.
2) 배역 배분: 인형을 모두 넣은 뒤, PuppetBrain.Create 전에 DirectorCasting.Assign(world)를 부른다. PrototypeSettings에 UseDirectorCasting(기본 true)을 두고, false면 지금처럼 자리 순서로 배역을 준다(앞 둘 Guard, 뒤 왼쪽 Attacker, 뒤 오른쪽 Healer).
3) 자리 순서로 배역을 가정하는 곳을 모두 실제 배역으로 바꾼다. 지금 확인된 곳: (a) PrototypeJointAttack.Expedition.cs의 PerformPlayerAttack이 AttackTarget에 'i < 2 ? Guard : i == 3 ? Healer : Attacker'를 넘긴다. 이것이 연출가의 관찰(힐러 집중 등)에 들어가므로 World의 그 개체 Role(배분된 배역)을 넘긴다. (b) ApplyFormation의 GuardHealer 진형은 자리 1을 자리 3 뒤로 옮긴다. 배분된 배역 기준으로 바꾼다: Healer 배역이 있고 Guard 배역이 둘 이상이면, AgentId가 큰 Guard를 Healer 뒤(GuardHealerOffset)로 옮긴다. 아니면 옮기지 않는다. 배역은 진형 위치를 넣은 뒤에 배분되므로, 배분 후 진형 위치를 다시 계산해 World 위치도 맞춘다(PuppetBrain.Create 전). (c) 그 밖에 자리 번호로 역할을 가정하는 코드가 있으면 같은 방식으로 바꾸고 기존 동작 변경 섹션에 적는다.
4) 장비 표시: 지금의 PrototypeEquipmentView.SetEquipment에 실제 Loadout의 EquipmentIds를 넘기는 흐름은 그대로 쓴다(라인업이 바뀌면 표시도 바뀐다).
5) F1 개발 오버레이에 인형마다 다음을 더한다: 배역과 계약 목표(RoleContract.ForRole(role).Goal), 지금 행동이 계약의 우선 / 대체 / 계약 밖 중 무엇인지(RoleContract.Classify), 능력 태그와 공격 거리·이동 속도 배율, 실 장력(World.GetPuppetState). 기존 표시(현재 행동, 대상, 상위 3개 점수)는 유지한다. 교전 사이 화면(오버레이 켰을 때)에 이번 교전의 라인업 이름(A/B/C)과 배역 배분 결과를 한 줄로 보여 준다.
수치와 라인업은 PrototypeSettings에 두고 임의로 정한 값임을 표시한다. 사람이 할 일에 'PrototypeBootstrap 컴포넌트 Reset'이 필요한지 적는다.
테스트: 규칙 코어 테스트(dotnet test tests/Core.Tests --no-restore -m:1)는 계속 통과해야 한다(Core를 바꾸지 않으므로 그대로여야 한다).
마지막 메시지에 '검증 근거' 표를 둔다: 위 1)~5) 각 항목마다 바꾼 파일과 메서드 이름. 그리고 '자리 순서로 배역을 가정하던 곳' 목록(찾은 곳 전부, 고쳤는지)과 Play에서 확인할 항목을 적는다.
