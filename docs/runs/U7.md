프로토타입(Unity)에서 인형 행동의 수치를 Play 중에 바꿔 보며 감각을 맞출 수 있게 하고, F1 개발 오버레이가 유닛을 가리지 않게 한다. 지금은 Play 피드백("동작은 하는데 굼뜨고, 앞으로 살짝 왔다가 몇 초 뒤 물러나는 식으로 불연속적")을 고치려면 숫자 하나를 바꿀 때마다 jevcode run을 돌려야 한다. 이 run은 Core의 수치를 Unity에 연결만 한다. src/Core는 바꾸지 않는다(필요한 API가 없으면 고치지 말고 제안 섹션에 적는다). Core의 기본값도 바꾸지 않는다.

1) 자동 연결(설정이 늘어도 Unity 코드를 고치지 않게): PrototypeSettings(PrototypeBootstrap 컴포넌트 안의 직렬화 클래스)에 목록 'PuppetTuning'을 둔다. 항목 = { 이름(문자열), 값(double) }. 이름은 '<클래스 이름>.<매개변수 이름>'이다(예: BasicActionSettings.harassIntervalTicks, SurroundSettings.attackerWeight). 클래스마다 같은 매개변수 이름이 있어도 헷갈리지 않게 하려는 것이다.
   설정 객체 만들기: Core의 PuppetSettings를 매개변수가 가장 많은 공개 생성자로 만든다. 그 생성자의 매개변수를 리플렉션으로 읽어, 숫자(int, double, float) 매개변수는 기본값(ParameterInfo.DefaultValue)으로 채우고 목록에 같은 이름(대소문자 무시)이 있으면 그 값으로 바꾼다(int는 반올림). 매개변수의 타입이 Core의 다른 설정 클래스(지금은 BasicActionSettings와 그 안의 SurroundSettings)이면, 그 클래스도 같은 방식(매개변수가 가장 많은 공개 생성자, 숫자는 기본값과 목록, 설정 클래스는 다시 같은 방식)으로 만들어 넘긴다. 그 밖의 매개변수(roleWeights 같은 표)는 기본값(null)이다. 그래서 Core에 설정 클래스나 숫자 매개변수가 늘어도 Unity 코드를 고치지 않는다.
   목록에 있지만 어느 매개변수와도 맞지 않는 이름은 Console Warning과 화면 경고(아래 5)) 뒤 무시한다.
2) 목록 채우기: ContextMenu는 컴포넌트에만 붙으므로 PrototypeBootstrap 컴포넌트에 ContextMenu '인형 수치 목록 채우기'를 둔다. 누르면 1)에서 따라가는 모든 설정 클래스의 숫자 매개변수 전부를 '<클래스>.<매개변수>' 이름과 Core 기본값으로 settings.PuppetTuning에 넣는다(이미 있는 이름은 값을 유지). 인스펙터에서 바로 고칠 수 있게 하려는 것이다.
3) 기존 필드 옮기기: 지금 InitializeBrain이 PrototypeSettings의 개별 필드(PuppetInterceptDistance, PuppetSpreadDistance, PuppetAttackRange, PuppetMoveSpeed, PuppetDistanceScale, PuppetApproachWeight, PuppetInterceptWeight, PuppetSpreadWeight, PuppetHoldWeight, PuppetAttackWeight, PuppetInterceptPositionFloor, PuppetPersistenceBonus, PuppetMidAttackRange, PuppetRangedAttackRange)를 넘긴다. 이 중 값이 Core 기본값과 다른 것은 같은 값으로 PuppetTuning 목록의 기본 항목에 넣고, 개별 필드는 지운다(이 필드들은 InitializeBrain 말고는 쓰는 곳이 없다). 그래서 이 run 전과 같은 값으로 동작해야 한다. 값 비교는 float를 double로 바꾸며 생기는 오차를 무시한다: |a - b| <= 1e-6 × max(1, |b|)이면 같다(예: 0.2f와 0.2는 같다). 지금 14개 필드의 값은 모두 Core 기본값과 같으므로 옮겨질 항목은 없을 것이다(그러면 근거 표에 '없음'으로 적는다). arenaHalfSize, ticksPerSecond처럼 장면에서 계산하는 값은 지금처럼 코드가 넘기고 목록에 두지 않는다. 근거 표에 옮긴 필드와 값을 적는다.
4) 적용 시점: 교전 시작 때 적용한다. F5를 누르면 지금 교전에 바로 다시 적용한다: 같은 World(위치, 상태, 장비, 배역 유지)로 PuppetBrain을 새로 만든다. 진행 중이던 판단은 처음부터 다시 시작해도 된다.
5) 잘못된 값: Core가 설정을 거부하면(생성자 예외나 PuppetBrain.Create 실패) 프로토타입을 멈추지 않는다. 화면 왼쪽 위에 경고를 3초 띄우고 Console에 Warning을 남긴 뒤 이전 설정을 쓴다. 교전 시작 때 거부되면 Core 기본값으로 시작하고 같은 경고를 띄운다.
6) 값 기록: F6을 누르면 지금 적용 중인 값 중 Core 기본값과 다른 것만(3)의 오차 규칙) 'Class.name=Value' 형식 한 줄(쉼표로 구분, 값은 소수 넷째 자리까지)로 Console에 Log로 남기고 클립보드(GUIUtility.systemCopyBuffer)에 복사한다. 다른 값이 없으면 '기본값과 같음'. 키 입력은 지금 F1처럼 Input System(Keyboard.current)을 쓴다.
7) F1 오버레이 위치: 지금 인형 라벨(DrawBrainOverlay의 GUI.Box)은 인형 위 BrainLabelHeight 지점을 상자의 '위쪽 모서리'로 그려서, 상자가 아래로 내려와 인형을 가린다. 바꾼다: 기준점 = 인형 렌더러(장비 표시 포함)의 경계 맨 위 + BrainLabelMargin(기본 0.3 월드 단위, 새 설정). 상자는 기준점 위로 그린다(상자의 '아래쪽 모서리'가 기준점). 상자가 화면 위로 넘치면 화면 안으로 끌어내린다. 인형끼리 상자가 겹치는 것은 이번에는 다루지 않는다.
8) 표시: F1 오버레이 맨 위(화면 위쪽, 인형 라벨과 별개)에 판단 주기, 이동 속도, 견제 주기·회복, 측면 돌기 반경과 '기본값과 다른 항목 수'를 한 줄로 보여 준다. 조작 안내에 F5(수치 다시 적용), F6(수치 기록)을 더한다.
사람이 할 일에 'PrototypeBootstrap 컴포넌트 Reset'이나 ContextMenu 실행이 필요한지 적는다. 규칙 코어 테스트(dotnet test tests/Core.Tests --no-restore -m:1)는 계속 통과해야 한다(Core를 바꾸지 않으므로 그대로여야 한다).
마지막 메시지에 '검증 근거' 표를 둔다: 1)~8) 각각 바꾼 파일과 메서드 이름. 그리고 3)에서 목록으로 옮긴 필드와 값(없으면 '없음'), ContextMenu로 채워지는 매개변수 개수를 클래스별로(PuppetSettings, BasicActionSettings, SurroundSettings) 적는다.

## 리뷰 포인트
- [리뷰 화면] 변경 파일 → src/Core 아래 파일이 없다
- [근거 표] 옮긴 필드 목록 → 옮긴 값이 이 run 전 PrototypeSettings의 값과 같다
- [Play] 아무것도 바꾸지 않고 교전 1을 한다 → 이 run 전과 같은 행동이고, F6을 누르면 '기본값과 같음'
- [Play] PrototypeBootstrap 컴포넌트의 우클릭 메뉴 '인형 수치 목록 채우기' → 목록에 PuppetSettings.reevaluationIntervalTicks, BasicActionSettings.harassIntervalTicks, SurroundSettings로 시작하는 이름들이 Core 기본값으로 나타난다
- [Play] 목록에서 PuppetSettings.reevaluationIntervalTicks를 30에서 10으로 바꾸고 F5 → 인형들의 반응이 눈에 띄게 빨라진다
- [Play] PuppetSettings.keepMax를 keepMin보다 작게 바꾸고 F5 → 경고가 뜨고 게임이 멈추지 않으며 이전처럼 움직인다
- [Play] 값을 두어 개 바꾸고 F6 → Console에 바꾼 항목만 한 줄로 나오고, 메모장에 붙여 넣으면 같은 줄이 나온다
- [Play] F1 → 각 인형의 라벨 상자가 인형 머리 위에 떠 있고 인형 몸과 장비를 가리지 않는다
