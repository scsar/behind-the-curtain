src/Core의 막아서기(intercept)와 힐러의 거리 유지(keepDistance)를 고친다. 이 명령은 거절된 run 20261005-212613-5e9f(T16b-2f)의 재시도다. 그 run의 문제 세 가지와, Play에서 본 네 번째 문제를 모두 막아야 한다. (1) 막아서는 개체가 제자리에 멈춘다(원래 문제). (2) 고친 뒤 플레이어가 멈추면 막아서는 개체와 힐러가 좌우로 빠르게 떤다: 막아서기 목표는 힐러 위치에, 힐러 목표는 막아서는 개체 위치에 의존해서 둘이 매 tick 서로를 쫓았다. (3) 막아서기 품질 지표가 100%, 평균 0.005m로 나왔지만, 힐러가 막아서는 개체 뒤로 줄을 서서 생긴 값이라 아무것도 검증하지 못했다. (4) 플레이어가 막아서는 인형들 사이를 지나 힐러 쪽으로 가면, 막아서던 인형이 힐러 쪽으로 넘어와 다시 막지 않고 반대편에 서 있다: 막아서기 적합도가 "공격 거리 안에 사람이 있으면 0"이라 지나치는 순간 attack(제자리 행동)으로 바뀌고, 목표로 가는 직선이 플레이어를 통과한다. 플레이어의 방향(정면)은 쓰지 않는다. 위치 관계만으로 판단한다. Unity 코드는 바꾸지 않는다. 공개 API는 유지한다. 아래에 적지 않은 행동(approach, attack, hold, spread, pressure, waver)과 그 이동 제약은 바꾸지 않는다.

1) 막아서기 목표: 막아서는 개체(intercept 예약의 주인)의 목표 지점 = 선분 S 위에서 그 개체의 현재 위치에 가장 가까운 점. S는 힐러에서 위협자 쪽으로 InterceptDistance(기본 1.5m) 떨어진 점부터, 위협자에서 힐러 쪽으로 InterceptStandOff(기본 1.0m, 새 설정) 떨어진 점까지다. 힐러-위협자 거리가 두 값의 합보다 짧으면 S는 힐러에서 InterceptDistance 지점 한 점이다.
2) 막아서기 여유 구간: 막아서는 개체와 S 사이 거리가 InterceptHoldTolerance(기본 0.3m, 새 설정) 이하이면 목표 = 현재 위치(움직이지 않는다). 초과이면 1)의 점으로 간다.
2-1) 지나쳐진 막아서기는 공격보다 우선: 막아서는 개체가 위협자 뒤쪽에 있으면(위협자-힐러 거리 < 막아서는 개체-힐러 거리) 공격 거리 안에 사람이 있어도 intercept 적합도를 0으로 만들지 않는다. 그 밖의 경우 "공격 거리 안이면 intercept 0" 규칙은 그대로다.
2-2) 돌아 들어가는 경로: 막아서는 개체의 현재 위치에서 목표 지점으로 가는 직선이 위협자에게서 InterceptClearance(기본 1.0m, 새 설정)보다 가깝게 지나가면, 위협자를 옆으로 InterceptClearance만큼 비켜 가는 경유점(직선에 수직, 위협자에서 InterceptClearance 떨어진 두 점 중 개체에 가까운 쪽)으로 먼저 간다. 경유점에 0.2m 안으로 오면 원래 목표로 간다.
3) 막아서기 이동 제약: intercept는 '위협 반경 안의 사람에게서 멀어지는 이동 금지'(PuppetActions.ConstrainMovement)에서 뺀다. 금지 패턴 '이유 없는 도망'의 판정에서도 intercept 중인 tick은 세지 않는다.
4) 힐러 거리 유지와 순환 끊기: 힐러를 막아서는 개체가 있을 때(블랙보드에 'intercept:<힐러 id>' 예약이 유효할 때) 힐러의 keepDistance는 Guard 위치를 쓰지 않는다. 방향 = 가장 가까운 사람에서 힐러 현재 위치로의 방향(지금 방향 유지). 거리가 KeepMin~KeepMax 안이면 목표 = 현재 위치(움직이지 않는다). 밖이면 같은 방향으로 가장 가까운 경계(KeepMin 또는 KeepMax)까지만 간다. 막아서는 개체가 없을 때의 keepDistance는 지금과 똑같이 둔다(가장 가까운 Guard 뒤).
5) 새 금지 패턴 '위치 떨림'(항상 금지): 개체마다 tick 사이 이동 벡터 d를 본다. 연속한 두 이동 d(t-1), d(t)가 둘 다 0.001m보다 길고 내적이 0보다 작으면 '방향 뒤집힘' 1회다. 어떤 1초(30 tick) 구간에서도 개체 하나의 방향 뒤집힘이 JitterMaxReversals(기본 3, 새 설정)를 넘으면 실패. 기존 '진동'(행동 전환 횟수)과 별개로, 같은 행동 안에서 위치가 왔다 갔다 하는 것을 잡는다. src/Core.Sim의 금지 패턴 지표 출력에 개체별 최대 방향 뒤집힘(1초 구간)을 더하고, docs/ai-design.md 금지 패턴 표에 이 행을 더한다.
6) 새 시나리오 둘(src/Core.Sim --puppets, 기존 approach·circle·retreat·healer는 바꾸지 않는다):
   standstill = healer 시나리오와 같은 힐러 위협 기억으로 시작. 플레이어가 (0, 12)에서 5m/s로 (0, 4)까지 와서 그 뒤 10초가 끝날 때까지 멈춘다.
   passby = 같은 힐러 위협 기억. 플레이어가 파티 정면 (0, 12)에서 출발해 5m/s로 두 Guard 시작 위치 사이를 지나, 힐러 시작 위치에서 3m 떨어진 지점(힐러 쪽으로 가는 직선 위)까지 와서 10초가 끝날 때까지 멈춘다.
   orbit = 같은 힐러 위협 기억. 힐러(13)는 시작 위치에 고정한다(시뮬레이터가 매 tick 힐러 위치를 시작 위치로 되돌린다. 테스트용 장치이며 Core 규칙이 아니다). 플레이어는 힐러를 중심으로 반지름 6m 원을 0.5 rad/s로 돈다. 힐러가 움직일 수 없으므로 선분 위에 서는 것은 막아서는 개체가 직접 따라가야만 가능하다.
7) 막아서기 품질 지표(src/Core.Sim): intercept 중인 tick 수, intercept를 시작한 뒤 처음 30 tick(정착 시간)을 뺀 tick 중 S까지 거리 1.0m 이하의 비율, 평균 거리, 그리고 그 구간에서 막아서는 개체가 실제로 움직인 총거리. intercept tick이 0이면 비율을 0으로 출력하지 말고 'n/a(막아서기 없음)'으로 출력한다.
수치는 설정에 두고 임의로 정한 값임을 표시한다.
테스트(tests/Core.Tests): (a) standstill: 플레이어가 멈춘 뒤 마지막 4초 동안 모든 개체가 위치 떨림 기준을 통과하고, 막아서는 개체와 힐러가 마지막 3초 동안 각각 0.2m 넘게 움직이지 않는다. (b) orbit: intercept tick이 0보다 크고, 정착 뒤 비율이 0.80 이상, 막아서는 개체가 움직인 총거리가 3m 이상(따라간 증거). (c) healer: 플레이어가 움직이는 동안 막아서는 개체가 1초 넘게 같은 위치(0.01m 이내)에 머무르지 않는다. (d) 여유 구간 경계: 막아서는 개체가 S에서 0.29m면 목표 = 현재 위치, 0.31m면 S 위의 점. 힐러가 막아서는 개체가 있고 사람과 6m(KeepMin 5 ~ KeepMax 8 안)면 목표 = 현재 위치, 4m면 같은 방향으로 5m 지점. (e) 막아서는 개체가 없을 때 힐러의 keepDistance 목표는 이 run 전과 같다. (f) 기존 금지 패턴과 새 '위치 떨림'이 approach, circle, retreat, healer, standstill, orbit, passby 일곱 시나리오와 --loadout mixed --cast, --loadout noprotect에서 모두 통과한다. (g) approach, circle, retreat 시나리오의 궤적은 이 run 전과 같다(intercept가 없는 시나리오). (i) passby: 플레이어가 두 Guard 시작 위치를 잇는 선을 지난 tick부터 2초(60 tick) 안에 막아서는 개체가 선분 S에서 1.0m 이내로 돌아오고, 그 뒤로 끝까지 대부분(80% 이상) S에서 1.0m 이내다. 지나는 동안 막아서는 개체와 플레이어 사이 거리가 0.5m 미만이 되지 않는다(통과하지 않음). (j) 2-1) 경계: 막아서는 개체가 위협자보다 힐러에서 멀면 공격 거리 안이어도 intercept 적합도 > 0, 가까우면 공격 거리 안에서 0. (h) 결정론. 규칙 코어 테스트는 계속 통과해야 한다. healer 시나리오의 궤적이 바뀌는 것은 의도한 것이다. 궤적을 고정한 기존 테스트를 고쳤다면 무엇을 왜 바꿨는지 기존 동작 변경 섹션에 적는다.
