# 기획 결정 및 다음 작업

## 현재 방향

- Unity 기반 1인 개발, 클라이언트 및 서버 직접 구현 지향.
- 포트폴리오 제작과 실제 출시를 함께 목표로 함.
- 소수 인원으로 시작하는 지속형 온라인 RPG.
- 플레이어는 인형을 부리는 대신 직접 전투.
- 인형사가 적 파티의 전술을 바꾸고, 플레이어는 조종 실에 카운터로 간섭.
- 하나의 공연을 중단시키기 위해 관문을 진행하며, 같은 인형사가 다음 관문의 편성·배치·행동을 조정.
- 교전 → 대응 변화의 단서 확인 → 파티 정비 → 다음 교전.
- 적의 대응에는 새 약점이 생김. 기존 전략도 유효하고, 변화를 읽고 대응하면 더 유리한 전투를 지향.
- 전술 수정은 교전 사이에 적용. 카운터 신호·판정은 일관되게 유지하고 매 관문 세팅 교체는 강제하지 않음.

## 우선 결정할 사항

- [ ] 시각적 분위기, 캐릭터 비율, 카메라 시점.
- [ ] 첫 검증에 사용할 무기와 역할 구성.
- [ ] 카운터 신호, 판정, 실패 후 수습 규칙. (간섭 방식의 역할 분담은 아래 "카운터 간섭 방식"에 진행 중)
- [ ] 적이 관찰할 행동과 대응 전술의 최소 집합.
- [ ] 각 대응의 이점·약점과 플레이어에게 전달할 단서.
- [ ] 관문별 스토리 목적과 정찰·정비 구간, 변경 가능한 세팅 범위.
- [ ] 원정 완료 후 재도전 동기와 보상 구조.
- [ ] 생활 콘텐츠의 핵심 재미와 첫 버전 포함 범위.
- [ ] Unity 버전과 네트워크·서버 기술 선정.

## 카운터 간섭 방식 (프로토타입에서 검증 중)

세 방식은 사거리로 나누지 않고 **각자 다른 대가**로 역할을 나눈다. 판정 규칙(끊었는지, 창 안인지)은 규칙 코어가 맡고, 대가는 입력 조건으로 둔다. 수치가 굳으면 규칙 코어로 옮긴다.

| 방식 | 대상 | 대가 | 역할 |
|---|---|---|---|
| Cut | 실(Thread) | 근접 사거리. 즉시 끊음 | 파고들어 바로 자르기 |
| Shoot | 고정점(Anchor) | 정지 조준 + 쿨다운. 겨냥한 방향에 있어야 하고, 인형 몸통에 가려지면 못 쏨 | 자리를 잡아 한 발씩 아껴 쏘기. 후면 고정점은 돌아 들어가야 함 |
| Disrupt | 신호(Signal) | 정지 채널링. 대신 범위 안의 신호를 한꺼번에 끊음 | 모인 신호를 한 번에 처리 |

- 대가는 **압박이 있어야** 의미가 생긴다. 가만히 서 있어도 위험하지 않으면, 조준과 채널링은 시간만 잡아먹는다. 그래서 합동 공격 동안 인형이 움직이고, 바닥 경고 범위에 선 플레이어는 피격된다(피격 시 조준·채널링 취소).
- **지금의 압박은 임시다.** 파티 회전과 플레이어 발밑의 바닥 경고(U3d, `PrototypeJointAttack.Pressure.cs`)는 카운터 대가를 검증하기 위한 자리표시다. 이후 인형의 교전 중 행동은 Utility AI나 블랙보드 같은 별도 시스템으로 대체한다. 역할 분리 예상: 연출가(교전 사이, 전술 선택) → 블랙보드(공유 상태) → 인형별 행동 선택(교전 중). 이 파일의 회전과 경고 로직 위에 새 기능을 쌓지 않는다.
- 협동에서의 기대: 한 명이 채널링하는 동안 다른 한 명이 실을 자르는 식의 분담. 아군 봇은 이후 단계.
- 검증 순서: 방식별 대가(U3b) → Shoot 겨냥과 가림(U3c) → 압박(U3d) → 연출가 적응(U4). 한 번에 하나씩 바꿔서, 어떤 변경이 체감을 바꿨는지 구분한다.
- **원칙: 카운터는 한 번 누르면 끝나는 입력이 아니다.** 일반 전투는 일반 전투대로 하고, 카운터는 그 위에 얹히는 부가 핵심 시스템이다. 핵심 기믹이므로 자리 잡기, 조준, 채널링 같은 투자를 요구하는 게 맞다(2026-09-22 사용자 판단).
- 이후 후보(필요할 때만): 혼자 테스트할 때 가상 아군을 두어 바닥 경고를 분산(`SimulatedAllies`). 피격 시 전부 취소 대신 진행도 일부만 잃기. 다인 테스트 전까지 U3e의 경고 주기로 버틸 수 있는지 먼저 본다.
- 이후 후보(U4 다음): **카운터 습관도 연출가의 학습 대상에 넣는다.** 지금 연출가는 공격 습관(광역 의존, 힐러 집중, 원거리 비율)만 관찰하고, 연결부 배치는 거기서 나온 대응으로 정해진다. 그래서 카운터 시스템과 학습 루프가 떨어져 있다. 예: Disrupt로 신호를 몰아서 끊으면 다음 교전에서 신호를 흩어 놓고, 먼 거리 Shoot 습관이 보이면 고정점을 몸통 뒤에 숨기고(가림), Cut으로 파고들면 실 근처에 바닥 경고를 늘린다(압박). 규칙 코어(관찰 항목, BehaviorProfile, JointAttackPlan) 변경이라 테스트와 함께 진행한다. U4에서 공격 습관 학습이 화면에서 읽히는지 먼저 확인한다.
- 플레이 기록(2026-09-22): U3는 거리만 달라서 Shoot이 늘 정답이었고, Cut과 Disrupt는 차이가 없었다. U3b 정적 테스트에서는 취소 사유가 "대상 없음"만 나왔고(압박 부재), Shoot은 시야 밖의 대상에도 쓰였다. U3d(압박): 피격 한 번에 모든 동작이 취소돼 빡빡하다. 바닥 경고가 1.5초마다 떨어지는데, 대규모 공격치고 주기가 너무 짧다. 혼자 테스트라 모든 공격이 한 사람에게 떨어지는 탓도 있다(다인 전제). 경고 주기(45tick)가 Disrupt 채널링(45tick)과 같아서, 움직이지 않고는 채널링을 끝낼 수 없는 구조였다. 인형 회전 속도 때문에 Cut을 쫓아다니는 문제는 없었다. U4r(연출가 적응): 의도대로 동작한다. 다만 적응이 **배치(진형, 연결부 위치)만 바꾸고 행동은 바꾸지 않아서** 체감이 약하다. 반면 **연결부가 어디에 무엇이 있는지 찾아보는 과정은 확실히 재미 요소**다(읽기 → 대응). 적응을 체감시키려면 대응이 인형의 교전 중 행동까지 바꿔야 한다. 이건 임시 압박을 대체할 인형 AI(블랙보드 → 인형별 행동 선택) 단계와 이어진다.

## 공격 속성과 파츠 (초안)

현재의 근접·원거리·광역은 프로토타입용 최소 분류다. 최종 전투는 원소 상성표보다 **공격이 어떤 전투 상태를 유도하는가**를 중심으로 확장한다. 속성은 원소가 아니라 행동 특성으로 정의한다.

| 공격 특성 | 유도하는 변화 |
|---|---|
| 절단 | 실·관절·연결부에 누적 피해를 주고 연결을 약화 |
| 타격 | 자세 게이지를 크게 줄이고 방어 자세를 붕괴 |
| 관통 | 몸체나 전방 방어를 넘어 후방 파츠·고정점을 노림 |
| 압박 | 이동·진형 변경을 방해하고 특정 위치에 몰아넣음 |
| 교란 | 인형사의 명령, 합동 공격 준비, 대상 우선순위를 흔듦 |

일반 공격의 절단·교란은 누적 효과이고, 카운터의 Cut·Disrupt는 열린 카운터 창에서 확정적으로 연결을 처리한다. 같은 개념을 공유하지만 일반 전투와 카운터의 역할은 구분한다.

초기 파츠는 네 종류를 후보로 둔다.

| 파츠 | 역할 | 파츠 공략 결과 |
|---|---|---|
| 몸체 | 기본 생명력과 일반 공격 대상 | 일반 피해 |
| 관절 | 이동과 자세 유지 | 자세 붕괴·이동 지연 |
| 연결 실 | 인형과 인형사의 연결 | 행동 약화·대상 변경 |
| 신호 장치 | 합동 공격 명령 전달 | 명령 지연·취소 |

고정점(Anchor)은 우선 연결 실의 물리적 위치로 다룬다. 별도 파츠가 필요한지는 플레이 검증 후 결정한다.

### 파츠 기회 공격

움직이는 인형의 작은 관절을 정밀 조준하는 구조는 사용하지 않는다. 인형의 공격·회복·방향 전환 등 특정 동작에서 파츠가 **노출 상태**가 되고, 플레이어는 그 방향과 범위에 공격해 파츠를 공략한다. 판정 영역은 실제 모델의 관절보다 넓게 두며, 타깃 고정과 약한 방향 보정을 허용한다.

이것은 기획상 ‘세미카운터’에 해당하지만, 플레이어 노출 명칭은 **파츠 기회 공격**으로 둔다.

- 일반 공격: 언제든 사용하며 체력과 압박을 누적.
- 파츠 기회 공격: 적의 동작을 읽고 노출된 파츠에 공격해 자세·행동을 약화.
- 실 카운터: 인형사의 합동 명령으로 열린 창에 대응해 공격을 차단하거나 크게 약화.

파츠 기회 공격은 전투를 유리하게 만드는 선택지이며, 놓쳤다고 전투가 중단되지는 않는다. 실 카운터는 큰 위협에 대한 대표 대응이므로 둘을 같은 타이밍 입력 시스템으로 만들지 않는다.

초기 검증에서는 무기 세 종류와 파츠 세 종류(관절·연결 실·신호 장치)의 차이가 실제로 다른 선택을 만드는지 먼저 확인한다. 무기별 파츠 우위가 항상 정답이 되지 않도록, 인형사는 방어 위치·이동·호위 행동으로 대응할 수 있어야 한다.

**정해야 할 것:**

- ~~연결 실 파츠와 카운터의 Thread 연결부는 같은 실인가?~~ **결정(2026-09-22): 별개다.** 연결 실 파츠 약화는 통제 안정성과 행동 우선순위에 영향을 주고, 창 안의 Cut 카운터에는 영향을 주지 않는다. 신호 장치와 Signal 연결부도 같은 원칙으로 둔다.
- 관통은 실 카운터에도 적용되나? 적용되면 Shoot 카운터의 몸통 가림이 무의미해진다. 추천: 일반·파츠 기회 공격에만 적용.

AI가 이 규칙을 어떻게 관찰하고 대응하는지는 `docs/ai-design.md`에 둔다.

## 장비 구조 (초안)

초기 장비는 **무기 / 방어구 / 무대 도구** 세 파트로만 구성한다. 세트 효과, 장식 슬롯, 복잡한 부위별 옵션은 전투 핵심이 검증된 뒤에 검토한다.

장비의 목적은 수치 경쟁보다 **플레이어의 전투 행동과 맡을 수 있는 기회를 바꾸는 것**이다. 직업을 장비로 고정하지 않으며, 같은 무기라도 방어구와 무대 도구 조합에 따라 다른 역할을 수행할 수 있어야 한다.

| 장비 | 담당 | 초기 설계 기준 |
|---|---|---|
| 무기 | 직접 공격 방식과 주력 공격 특성 | 모션, 사거리, 이동, 관절·실·신호에 대한 영향이 달라짐 |
| 방어구 | 생존 방식과 기본 행동 보정 | 자세 저항, 채널링 유지, 회피 후 안정성 등으로 제한 |
| 무대 도구 | 실 카운터의 접근 방식 보조 | Cut·Shoot·Disrupt 중 하나를 강화하지만 기본 세 방식은 모두 사용 가능 |

무기 예시는 절단검, 타격 망치, 관통창·쇠뇌, 교란 지팡이처럼 공격 특성과 움직임이 다른 구성으로 시작한다. 방어구는 직업을 부여하지 않고 특정 상황의 생존과 행동 유지에 영향을 준다. 무대 도구는 특정 카운터를 잠그는 열쇠가 아니라 접근 비용을 낮추거나 실패를 수습하는 보조 장비로 둔다.

### 장비와 전투 패턴

연출가는 플레이어가 장착한 장비 이름이나 속성을 직접 카운터하지 않는다. 실제 전투에서 반복된 행동을 관찰하고, 그 행동에 대응하는 인형의 패턴을 선택한다.

```text
장비 조합 → 플레이어의 실제 공격·이동·카운터 습관
         → 연출가의 관찰 → 인형의 보호·회전·분산·추적·미끼 패턴
```

대응은 기존 장비를 무효화하지 않고 새로운 약점과 선택지를 만든다. 장비를 바꾸지 않아도 패턴을 읽어 진행할 수 있어야 하며, 장비를 바꾸면 다른 방식의 기회를 얻는 정도로 설계한다.

**첫 검증 질문:** 무기를 바꾸면 공격과 이동이 달라지는가? 방어구가 역할을 고정하지 않고 생존·행동 유지 방식을 바꾸는가? 무대 도구가 세 카운터의 접근 비용과 위험을 다르게 만드는가? (제안) 연출가의 대응이 특화를 무력화하지 않고 난이도만 올리는가? 예: Disrupt 도구로 특화한 플레이어에게 신호를 흩어 놓아도, 여전히 그 빌드로 진행할 수 있는가.

### 적응 변화의 전달 원칙

연출가의 대응 변화는 플레이어가 읽고 추론할 수 있어야 하지만, UI나 문구로 직접 설명하지 않는다. 인형의 간격, 이동 방향, 보호 위치, 파츠 노출 방향, 준비 동작, 짧은 지시와 같은 세계 안의 단서로 전달한다.

첫눈에는 새로운 패턴처럼 보이되, 몇 번 관찰하면 이전 플레이와의 관계를 추론할 수 있어야 한다. 대응을 알아내면 새로운 약점과 선택지도 함께 보여야 하며, 잘못 추론해도 전투를 계속할 수 있어야 한다. 적응을 알리는 전용 문구나 `광역 공격 대응 중` 같은 노출형 UI는 사용하지 않는다.

**보완(2026-09-22):** 대응은 항상 인형의 행동으로 드러나므로, 적응을 알려 주는 UI는 없어도 게임이 성립한다. 그래서 이런 UI는 기본 화면에 두지 않고, 필요하면 **보조 옵션**(난이도 설정에 가까운 선택)으로 검토한다. 개발 중의 상태 표시(대응 이름, 관찰 막대, 인형별 행동)는 리뷰와 원인 분석용으로 유지한다. 재미 검증은 이 표시를 보지 않고 행동만으로 읽히는지 확인한다.

### 파츠 공격의 행동 변화 원칙

파츠 공격은 피해량만 늘리는 수단이 아니다. 몸체 공격은 기본 피해와 처치 진행을 담당하고, 파츠 공격은 적의 **관찰 가능한 행동 변화**를 만들어야 한다.

| 파츠 | 대표 행동 변화 | 기본 보상 |
|---|---|---|
| 몸체 | 직접적인 행동 변화 없음 | 일반 피해와 처치 진행 |
| 관절 | 이동·회전·공격 준비가 느려지거나 취소됨 | 자세 붕괴·이동 지연 |
| 연결 실 | 통제 안정성·행동 우선순위가 흔들림 | 대상 변경·행동 약화 |
| 신호 장치 | 합동 공격의 순서·범위·대상이 달라짐 | 명령 지연·취소 |

초기에는 파츠마다 대표 행동 변화 하나를 우선 검증한다. 모든 파츠에 여러 상태 이상을 붙이지 않는다. 파츠를 약화했을 때 화면에서 실제 행동이 달라지는지, 플레이어가 그 차이를 공략 이유로 이해하는지를 확인한다.

## 첫 플레이 검증 후보

두 플레이어가 만나 적 인형 파티와 싸우고, 카운터로 합동 공격을 끊는다. 다음 교전에서 바뀐 적의 대응을 알아보고 전술을 수정한다. 보상을 받고 돌아온 뒤 재접속해 성장이 유지되는 것을 확인한다.

관문 사이에 다음 대응의 단서를 확인하고 정비할 기회를 둔다. 대응마다 새로운 약점을 발견할 수 있는지, 기존 세팅을 유지해도 진행 가능한지, 세팅 변경이 강제되는 피로감을 만들지 않는지 확인한다. 한 번에 두드러지는 변화는 우선 한두 개라는 임시 기준으로 검증한다.

두 명은 검증용 인원이며 최종 파티 정원은 미정이다. 재미 확인 이후 구현 범위와 일정을 구체화한다.

**방향(2026-09-22):** 파티는 4~5인으로 설계한다. 사람이 모자랄 때 빈자리를 채울 **아군 봇**이 필요하다. 인형 AI와 아군 봇은 같은 판단 구조(블랙보드 + 개체별 행동 선택)로 설계한다.

**다음 작업 순서(2026-09-22):**
1. 인형 AI와 아군 봇 설계(문서 먼저, 이후 규칙 코어 → Unity 연결). 연출가의 적응이 배치뿐 아니라 행동으로 드러나게 하는 것이 목적이다. 예: 힐러를 집요하게 노리는 플레이어를 Guard가 따라다니며 막는다.
2. 공격 속성과 파츠 세분화: 지금의 근접/원거리/광역 세 가지보다 세분화한다. 사용자가 별도로 정리해 가져온다.
3. 카운터 습관 학습(1·2가 정해진 뒤).
4. 연출과 스타일: 재미도를 올리려면 더 스타일리시해야 한다. 기본 루프가 선 뒤에 다룬다.
